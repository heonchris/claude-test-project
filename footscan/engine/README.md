# footscan engine — Phase 0 (파이썬 CV 파이프라인)

A4 용지를 기준자로 삼아, **사진만으로 발을 재는** 엔진입니다.
`SPEC.md` 의 Phase 0 을 그대로 구현했습니다. (앱은 아직 만들지 않았습니다)

```
사진 2장  →  A4 로 원근 펴기  →  발 분할  →  치수 측정  →  신발 사이즈
(위 / 옆)      1px = 0.1mm 고정
```

---

## 0. 휴대폰(안드로이드)에서 써보기 ★ 여기부터 보세요

앱을 설치하지 않습니다. **크롬으로 주소만 열면 됩니다.**

```
[안드로이드 폰]  사진 찍기 · 결과 보기      ← 크롬만 있으면 됨
       ↕  같은 와이파이
[PC]            계산 (파이썬 엔진)          ← python server.py
```

### 3단계로 끝

**1. PC 에서 서버 켜기**

```bash
cd footscan/engine
pip install -r requirements.txt      # 처음 한 번만
python server.py
```

화면에 이런 주소가 뜹니다.

```
    http://192.168.0.5:8000
```

**2. 폰에서 그 주소 열기**

폰과 PC 가 **같은 와이파이**에 있어야 합니다.
크롬 주소창에 위 주소를 그대로 칩니다. (숫자까지 똑같이)

크롬 메뉴 → `홈 화면에 추가` 를 누르면 바탕화면에 아이콘이 생겨 앱처럼 열 수 있습니다.
(주소가 `https` 가 아니라 집 와이파이용 `http` 라서, 진짜 앱처럼 전체화면으로 뜨지는 않습니다)

> ⚠️ **같은 와이파이에 있는 다른 사람도 이 주소로 들어올 수 있습니다.**
> 비밀번호가 없는 구조라, **집 와이파이에서만** 쓰고 카페·회사 공용 와이파이에서는 켜 두지 마세요.
> 올린 사진은 PC 에 1시간만 임시 보관되고 자동으로 지워집니다.

**3. 사진 찍고 측정**

화면 안내대로 A4 위에 발을 올리고 찍으면 됩니다.
위에서 찍은 사진 **1장**만 있어도 사이즈가 나오고, 옆면까지 찍으면 아치·발등도 나옵니다.

### 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| 폰에서 주소가 안 열림 | 폰과 PC 가 같은 와이파이인지 확인. PC 방화벽에서 8000 포트 허용 |
| "서버에 연결하지 못했습니다" | PC 의 `python server.py` 창이 꺼져 있는지 확인 |
| 주소가 매번 바뀜 | 공유기에서 PC 에 고정 IP 를 주면 편합니다 |
| 사진이 HEIC 라 거부됨 | 카메라 설정에서 저장 형식을 JPEG 로 바꿔 주세요 |

### 왜 폰 안에서 다 못 하나요?

측정 엔진이 **파이썬 + OpenCV** 로 되어 있어서 안드로이드 폰 안에서 직접 돌지 않습니다.
폰만으로 완결하려면 두 가지 길이 있는데, 둘 다 이 다음 단계입니다.

- 이 서버를 인터넷에 올리기 → 폰만 있으면 어디서나 됨 (PC 안 켜도 됨)
- SPEC Phase 4 처럼 알고리즘을 폰 안에서 도는 형태로 옮기기 → 개발량이 큽니다

지금 방식은 **집에서 바로 써보고 정확도를 확인하는 데** 목적이 있습니다.

## 1. 개발자용 — 명령줄에서 실행

```bash
cd footscan/engine
pip install -r requirements.txt

# 1) 합성 테스트 사진 만들기 (실제 사진이 없어도 검증할 수 있습니다)
python tests/make_synthetic.py

# 2) 측정
python cli.py --top samples/right_top.jpg --side-img samples/right_side.jpg \
              --foot right --debug --out results/

# 3) 회귀 테스트 (SPEC 3-8 완료 조건 검사)
python tests/test_measure.py

# 4) 한계 시험 (사진을 일부러 망가뜨려 어디서 깨지는지 확인)
python tests/stress_test.py

# 5) 서버 테스트 (폰에서 쓰는 경로가 살아있는지)
python tests/test_server.py
```

측면 사진은 **선택**입니다. 빼면 사이즈만 나오고 아치·발등은 "미측정"으로 표시됩니다.

양발을 한 번에:

```bash
python cli.py --right-top samples/right_top.jpg --right-side samples/right_side.jpg \
              --left-top  samples/left_top.jpg  --left-side  samples/left_side.jpg \
              --debug --out results/
```

## 2. 값을 조정하고 싶다면 — `footscan/config.py` 한 파일만 보세요

모든 기준 숫자(임계값)가 `config.py` 한 곳에 모여 있고,
각 숫자마다 **"올리면 / 내리면 어떻게 되는지"** 를 한글 주석으로 적어 두었습니다.
코드 안에는 숫자를 직접 쓰지 않았습니다.

특히 아래 값들은 **실측 데이터가 쌓이면 반드시 다시 맞춰야 하는 초기 가정치**입니다.

| 값 | 무엇을 정하는지 |
|---|---|
| `ARCH_CLEARANCE_LOW_MM` / `ARCH_CLEARANCE_HIGH_MM` | 아치 등급 경계 (8mm / 18mm) |
| `ARCH_GAP_RATIO_LOW` / `ARCH_GAP_RATIO_HIGH` | 비접지 구간 비율 경계 |
| `WIDTH_RATIO_*` | 폭 등급(좁음/보통/넓음/매우넓음) 경계 |
| `HVA_CALIB_SCALE` / `HVA_CALIB_OFFSET_DEG` | 무지외반 추정값 보정 |
| `SHOE_ALLOWANCE_MM` | 신발 종류별 여유분 |

숫자를 바꾼 뒤에는 `python tests/test_measure.py` 를 꼭 다시 돌리세요.

## 3. 지금 정확도 (합성 이미지 기준)

`python tests/test_measure.py` 가 검사하는 항목이자, 현재 통과 상태입니다.

| SPEC 3-8 완료 조건 | 결과 |
|---|---|
| A4 검출 20세트 중 18세트 이상 | **20/20** |
| 발 길이 정답 대비 ±3mm 이내 | **최대 오차 0.6mm** |
| 재현성: 같은 발 5회 길이 표준편차 2mm 이내 | **0.05mm** |
| 재현성: 같은 발 5회 아치 등급 불변 | **불변** |
| 교차검증 동작 | **동작** (다른 발 사진을 섞으면 신뢰도 0.3 + 재촬영 유도) |
| 에러 코드 4종 | `PAPER_NOT_FOUND` / `FOOT_NOT_FOUND` / `SIDE_REF_NOT_FOUND` / `LOW_CONFIDENCE` |
| 디버그 이미지 8장 | 저장됨 |
| 조용히 틀리는 조건 | **0건** (한계 시험 기준) |

> ⚠ **합성 이미지에서 통과 = 알고리즘이 맞다**는 뜻이지, **실사에서도 된다**는 보장은 아닙니다.
> 합성 이미지에는 렌즈 왜곡·짙은 그림자·발 두께·양말 질감이 없습니다.
> 반드시 실제 사진 20세트로 다시 검증하고, 줄자 실측과 비교하세요.

## 4. 한계 시험 — 얼마나 못 찍어도 버티나

`python tests/stress_test.py` 로 사진을 일부러 망가뜨려 가며 확인한 결과입니다.

**가장 중요한 결과: 틀릴 때는 반드시 사용자에게 알립니다.**
값이 틀렸는데 시스템이 모르는 "조용한 오류"는 0건입니다.
못 재는 조건은 에러로 막거나(차단), 신뢰도를 낮춰 재촬영을 요구합니다(경고).

| 조건 | 버티는 범위 | 넘으면 |
|---|---|---|
| 밝기 | 0.7 ~ 1.3배 | 어두우면 발을 못 찾음, 밝으면 발이 종이와 구분 안 됨 |
| 그림자 | 세기 0.2 미만 | 아치 값이 크게 틀어짐 (길이는 멀쩡) |
| 흔들림 | 블러 3px 이하 | 종이 검출 실패 |
| 노이즈 | 15 이하 | 아치 값이 틀어짐 |
| JPEG 압축 | **품질 15까지 문제없음** | (업로드 시 마음껏 압축해도 됩니다) |
| 카메라 기울기 | **2.5까지 문제없음** | 원근 보정이 잘 동작합니다 |
| 발을 비뚤게 놓기 | **30도까지 문제없음** | PCA 주축 정렬이 잘 동작합니다 |
| 양말 | 맨발·어두운 양말만 | **회색 양말도 실패합니다** (흰 양말만이 아님) |

여기서 나온 **앱 촬영 화면 요구사항**:
1. 실시간 **밝기 체크** — 너무 어둡거나 과노출이면 셔터 잠금 (가장 중요)
2. 실시간 **선명도 체크** — 흔들리면 셔터 잠금
3. **그림자 경고** — 화면 안 밝기 편차가 크면 경고
4. 양말 안내를 "흰 양말 X" → **"맨발 또는 어두운 색 양말"** 로 강화 (회색도 안 됨)
5. 자이로 ±5도 강제는 상면에서는 과할 수 있음 (30도 비뚤어도 정확). 다만 실제 렌즈 왜곡은 합성에 없으므로 실사 검증 후 완화 판단

## 5. Phase 0 을 만들며 알아낸 것 (실제 촬영·앱 설계에 반영해야 할 것)

1. **측면 촬영 시 발을 종이 긴 변의 '가운데'에 딛어야 합니다.**
   발이 종이의 양 끝을 가리면 297mm 기준 길이를 잴 수 없어 측정 자체가 불가능합니다.
   → 앱의 측면 촬영 가이드 문구/오버레이에 반드시 넣어야 합니다. (SPEC 5-4 8번 문구 보완 필요)

2. **그림자는 밝기만 바꾸고 색은 안 바꿉니다.**
   그래서 종이를 판정할 때 밝기(L)를 빼고 색감(a,b)만 봅니다.
   이 한 가지로 "발 밑 그림자를 발로 오인"하는 문제가 사라졌습니다.

3. **밝은 벽을 종이로 착각하는 사고가 잦습니다.**
   "검색 영역 맨 윗줄에 닿는 밝은 덩어리는 버린다"는 규칙 하나로 막았습니다.
   (바닥의 종이는 아래쪽 '띠'로 보이고, 벽은 위로 계속 이어지기 때문)

4. **길이 교차검증(B6)만으로는 부족합니다.**
   어두운 사진에서는 "발 길이는 맞는데 발바닥 아랫면만 깎여" 아치가 14mm → 26mm 로 튑니다.
   길이만 비교하는 B6 는 이걸 못 잡습니다.
   → **발바닥 접지 모양 점검**을 추가했습니다. 서 있는 발은 뒤꿈치·앞꿈치 딱 두 군데가
   닿아야 하고 뒤꿈치 접지가 발 길이의 20% 안팎이어야 하는데, 분할이 깨지면
   4~5조각으로 나뉘고 뒤꿈치 접지가 4% 로 떨어집니다. 이걸로 잡아냅니다.
   (`config.SIDE_MAX_CONTACT_RUNS`, `SIDE_MIN_HEEL_CONTACT_RATIO` 등)

5. **무지외반 추정값에는 계통 오차가 있습니다.**
   설계각 0/8/16/24도 → 측정 8.5/15.2/20.9/25.9도 (기울기 0.73, 절편 +8.5도).
   X-ray 계측값 몇 개만 확보하면 `config.HVA_CALIB_*` 로 맞출 수 있습니다.
   그때까지는 반드시 "외형 기반 추정"으로만 표기하세요.

6. **아치 지수(AHI)는 정의를 통일해야 합니다.**
   SPEC 은 `발등높이 / 전체 발길이` 로 정의하고 정상 범위를 0.32~0.37 이라고 했습니다.
   (임상에서 흔히 쓰는 "절단 발길이" 기준과 다른 값이니, 실측 보정 시 주의하세요)

## 6. 아직 안 만든 것 (SPEC 대비 빠진 것)

| 항목 | SPEC 위치 | 상태 |
|---|---|---|
| 발볼 둘레 줄자 실측 입력 옵션 | 1-2 | **미구현** — 폭 등급이 "너비 기반 추정"으로만 나옵니다 |
| 측면 정밀 모드 (x축 위치별 배율 보정) | 3-4 B2 주석 | 미구현 (SPEC 도 "v1은 단일 계수로 시작해도 됨") |
| 발자국(젖은 발) 정밀 아치 모드 | 3-5 | 미구현 (SPEC 상 선택 사항) |
| FastAPI 서버 + 휴대폰 화면 | Phase 1 | **완료** (`python server.py`) |
| React Native 앱 | Phase 2 | 미구현 — 지금은 크롬으로 쓰는 방식입니다 |

**의도적으로 SPEC 과 다르게 만든 것 2가지**

1. *"워핑 후 발 주축이 짧은 변과 평행하면 90도 회전"* → 캔버스를 돌리는 대신
   측정 단계에서 PCA 로 주축을 정렬합니다. 결과는 같고, 30도 비뚤어도 정확합니다.
2. *"측면에서 바닥의 밝은 사각형 컨투어 검출"* → 사각형이 아니라 **직선**을 찾습니다.
   발이 종이 가운데를 가려 사각형이 좌우로 쪼개지기 때문에, 사각형을 찾으면 실패합니다.
3. *"이미지 경계에 닿는 부분 제거"* → 뒤꿈치는 원래 종이 아래 가장자리에 닿으므로
   지우지 않고, 좌/우/위 경계에 닿으면 **경고 + 신뢰도 0.6** 으로 처리합니다.

```
│   ├── crosscheck.py     [B6] 상면 vs 측면 교차검증
│   ├── sizing.py         [4]  신발 사이즈 환산
│   ├── top/              위에서 찍은 사진 처리
│   │   ├── paper.py      [A2] A4 검출

│       ├── reference.py  [B2] A4 긴 변 = 기준자 + 바닥선
│       ├── segment.py    [B3] 발 분할 (rembg 또는 색 기반)
│       └── measure.py    [B4,B5] 아치·발등·등급
├── data/size_tables.json ★ 사이즈 대응표 (검증 후 교체 필요)

├── tests/
│   ├── make_synthetic.py 합성 사진 생성기
│   ├── test_measure.py   회귀 테스트 (정확한가?)
│   ├── test_server.py    서버 테스트 (폰에서 쓸 수 있나?)
│   └── stress_test.py    한계 시험 (얼마나 못 찍어도 버티나?)
├── web/                  ★ 휴대폰용 화면 (설치 없이 크롬으로 접속)
│   ├── index.html
│   ├── manifest.json     홈 화면에 추가했을 때 쓰이는 정보
│   └── icon-192/512.png
├── cli.py                명령줄에서 재기
├── server.py             ★ Phase 1 — 폰에서 쓰기 위한 서버
└── requirements.txt
```
