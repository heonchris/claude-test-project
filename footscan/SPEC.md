## 1. 시작 전 반드시 이해할 기술적 제약

### 1-1. 사진에는 절대 크기 정보가 없다

발이 큰 건지 카메라가 가까운 건지 사진만으로는 구분 불가입니다. 반드시 크기를 아는 기준물이 함께 찍혀야 합니다.
A4(210×297mm)를 쓰는 이유:

- 국제 규격이라 크기가 확정적이고 어디서나 구할 수 있음
- 발이 통째로 올라가는 **평면**이라 원근 왜곡을 수학적으로 완전히 펼 수 있음(호모그래피)
- 흰 배경이 되어 발 실루엣 분리가 쉬움 → AI 모델 없이 고전 CV만으로 가능

### 1-2. 상면 사진과 측면 사진이 각각 주는 정보

**상면(위에서) — 평면 치수. 정확도 높음(±3mm)**
- 발 길이, 발볼 너비, 뒤꿈치 너비
- 발가락 형태(이집트형/그리스형/로마형)
- 무지외반 각도 근사
- 좌우 비대칭

**측면(안쪽에서) — 높이 정보. 정확도 중간(±5~8mm)**
- 아치 들림 높이 (arch clearance)
- 아치 비접지 구간 길이
- 발등 높이 (instep height)
- 아치 지수 (Arch Height Index)

**두 장을 합쳐도 여전히 못 구하는 것**
- **발볼 둘레(ball girth)** — 신발 폭 규격 D/2E/4E의 실제 기준값. 3D 둘레라서 사진 2장으로는 불가.
  → 너비 기반 등급만 제공하고 "추정" 명시, 줄자 실측 입력 옵션 병행.
- 회내/회외(pronation) — 뒤꿈치 후면 사진 또는 족저압 데이터 필요.

### 1-3. 측면 촬영의 핵심 난제 — 기준 평면 문제 (가장 중요)

상면 사진은 A4가 발과 같은 평면(바닥)에 있어서 호모그래피가 완벽히 동작합니다.
**측면은 다릅니다.** 측정 대상(발 안쪽면)은 수직 평면인데, A4는 바닥에 누워 있습니다.
평면이 다르면 스케일이 맞지 않습니다.

검토한 해결책과 결론:

| 방안 | 문제 |
|---|---|
| 발 뒤에 A4를 세워 배경으로 사용 | 발 두께(~95mm)만큼 깊이 차 → 1m 거리에서 약 10% 오차(250mm 발에 25mm). **탈락** |
| 발 안쪽에 A4를 세움 | 카메라와 발 사이를 가림. **탈락** |
| **바닥 A4의 근거리 장변(297mm)을 스케일로 사용** | 발 안쪽 라인을 A4 장변에 맞춰 딛게 하면 기준선과 측정면이 거의 같은 수직 평면. **채택** |

**채택 방식 상세**

```
사용자는 발 안쪽(엄지 쪽) 라인을 A4의 긴 변에 맞춰 딛습니다.
카메라는 그 변 쪽에서, 변과 수직이 되도록 촬영합니다.

→ 화면에 보이는 A4 장변의 픽셀 길이 = 297mm  ⇒ px_per_mm 확정
→ 그 변 자체가 바닥선(높이 0 기준선) 역할
→ 발의 안쪽면이 이 변과 거의 같은 수직 평면에 있으므로 깊이 오차 최소화
```

추가 프롭이 전혀 필요 없다는 게 이 방식의 장점입니다. 대신 정확도는 상면보다 낮으므로,
**아치 높이는 정확한 mm 수치보다 3단계 등급(낮음/보통/높음)을 주 결과로 표시**하고
mm 값은 보조로만 표기합니다. 등급화가 오차에 훨씬 강합니다.

### 1-4. 상면↔측면 교차 검증 (품질 관리 장치)

같은 발을 두 각도로 찍었으므로 **발 길이가 두 사진에서 모두 나옵니다.**

```
if abs(길이_상면 - 길이_측면) > 6mm:
    → 측면 촬영 각도가 틀어졌다는 뜻
    → confidence 하향 + "옆면 다시 촬영" 유도
```

이걸 반드시 넣으세요. 사용자가 잘못 찍었는지 자동으로 알아내는 유일한 방법입니다.

### 1-5. 법적 표현 제한

한국 의료기기법상 "진단·질환 판별·치료" 표현을 쓰면 의료기기로 분류될 수 있습니다.

- 금지: "평발입니다", "무지외반증", "족저근막염 위험이 있습니다"
- 허용: "아치가 낮은 편으로 측정되었습니다", "참고용 측정값입니다"

모든 결과 화면 하단 고정: `본 측정값은 참고용이며 의료적 진단이 아닙니다.`

### 3-3. 파이프라인 A — 상면 (Top View)

#### A1. 전처리
- **EXIF 회전 보정 필수** (아이폰 사진은 회전 정보가 메타데이터에만 있음)
- 긴 변 1600px 리사이즈, 그레이스케일, 가우시안 블러 (5,5)

#### A2. A4 검출
```
1. Canny (threshold는 median 기반 자동 산출)
2. findContours(RETR_EXTERNAL)
3. 면적 상위 10개에 approxPolyDP(eps = 0.02 * arcLength)
4. 조건: 꼭짓점 4개 && 면적 > 전체의 15% && convex
5. 후보 중 종횡비가 √2(1.414)에 가장 가까운 것 선택 (원근 보정 전이므로 허용 ±25%)
6. 코너를 좌상-우상-우하-좌하로 정렬 (좌표합/차 이용)
```
실패 시 에러 코드 `PAPER_NOT_FOUND`

#### A3. 호모그래피 워핑 (핵심)
```
스케일: 10px = 1mm
목표 캔버스: 2100 x 2970 px (= 210 x 297 mm)
M = cv2.getPerspectiveTransform(src_corners, dst_corners)
warped = cv2.warpPerspective(img, M, (2100, 2970))
```
이 시점부터 **1px = 0.1mm**. 이후 모든 측정은 픽셀거리 ÷ 10 = mm.
워핑 후 발 주축이 짧은 변과 평행하면 90도 회전(A4 가로/세로 자동 판별).

#### A4. 발 분할
배경이 흰 종이이므로 AI 없이 가능:
```
1. BGR → LAB
2. L 채널 Otsu 이진화 (+ a/b 채널로 피부톤 보정, 맨발/양말 모두 대응)
3. 모폴로지 close(15x15) → open(9x9)
4. 최대 연결 요소만 유지
5. 이미지 경계에 닿는 부분 제거 (종이 밖으로 나간 발목/다리 절단)
6. approxPolyDP(eps=2)로 컨투어 스무딩
```
폴백: 그림자가 짙어 실패하면 `adaptiveThreshold` 경로로 재시도.

#### A5. 측정
```python
# 주축 정렬: PCA로 발 주축을 세로로 회전 (비뚤게 놓아도 보정)

foot_length_mm  = (max_y - min_y) / 10
ball_width_mm   = 뒤꿈치 기준 60~75% 구간의 최대 가로폭 / 10   # 제1~5 중족골두
heel_width_mm   = 뒤꿈치 기준 12~22% 구간의 최대 가로폭 / 10
width_ratio     = ball_width_mm / foot_length_mm

# 발가락 형태: 컨투어 상단에서 주축 방향 로컬 피크 5개 검출(최소 간격 조건)
#   |엄지 - 검지| < 2mm → roman / 엄지가 김 → egyptian / 검지가 김 → greek

# 무지외반 근사: 엄지 외측 윤곽 직선근사 vs 발 내측 라인 직선근사 사이 각
#   ⚠ 실제 HVA는 X-ray 골축 기준. 반드시 "외형 기반 추정" 라벨 표기
```

### 3-4. 파이프라인 B — 측면 (Medial View) ★신규

#### B1. 촬영 조건 (이게 안 지켜지면 알고리즘이 아무리 좋아도 무의미)
```
- 발 안쪽(엄지 쪽) 라인을 A4 긴 변에 맞춰 딛는다
- 카메라는 그 긴 변 쪽에서, 변과 수직으로
- 카메라 높이: 발목 높이 (바닥에서 약 10~15cm)
- 거리: 약 80~120cm  (가까우면 원근 왜곡, 멀면 해상도 부족)
- 폰은 지면과 수직 (자이로로 ±5도 이내 강제)
- 오른발은 왼쪽에서, 왼발은 오른쪽에서 촬영
```

#### B2. 기준 스케일 검출
```
1. 바닥면의 밝은 사각형(A4) 컨투어 검출
2. 카메라에 가장 가까운 장변 선분 추출 → 실제 297mm
3. px_per_mm = 선분_픽셀길이 / 297
4. 이 선분을 바닥선(floor line, height = 0)으로 등록
5. 선분이 수평이 되도록 이미지 회전 보정
```
실패 시 `SIDE_REF_NOT_FOUND`

> 원근 때문에 장변의 앞/뒤 픽셀 밀도가 다릅니다.
> 정밀 모드에서는 A4 네 코너 전부로 바닥 호모그래피를 구해
> x축 위치별 px_per_mm 보정 계수를 적용하세요. v1은 단일 계수로 시작해도 됩니다.

#### B3. 발 분할
측면은 배경이 방/벽이라 색 기반 분할이 안 됩니다. 두 경로:
```
경로 1 (권장, Phase 0): rembg(U2Net)로 배경 제거 → 알파 채널을 마스크로 사용
경로 2 (폴백): 사용자에게 "발 뒤에 어두운 색 수건/종이를 놓아주세요" 안내 후 색 기반 분할
```
분할 후 **바닥선 아래 영역은 잘라냄** (반사·그림자 제거).
Phase 4 온디바이스 전환 시에는 U2Netp 또는 MobileSAM으로 교체.

#### B4. 측정
```python
# 좌표계: x = 뒤꿈치(0) → 발끝, y = 바닥선(0) 위로 양수. 단위 mm.

foot_length_side_mm  = 마스크 x 범위 / px_per_mm      # ★ 교차검증용

# 접지 구간 판별: y < 3mm 인 마스크 하단 픽셀 = 바닥에 닿은 부분
heel_contact_end     = 뒤꿈치 쪽 접지 구간의 끝 x
forefoot_contact_start = 전족부 접지 구간의 시작 x

arch_gap_length_mm   = forefoot_contact_start - heel_contact_end
arch_gap_ratio       = arch_gap_length_mm / foot_length_mm

# 아치 들림 높이: 비접지 구간에서 마스크 하단 경계의 바닥선 대비 최대 높이
arch_clearance_mm    = max(하단경계 y for x in 비접지구간)

# 발등 높이: 발 길이 50% 지점에서 마스크 상단 경계 높이
instep_height_mm     = 상단경계 y at x = foot_length * 0.5
arch_height_index    = instep_height_mm / foot_length_mm    # 정상 대략 0.32~0.37
```

#### B5. 아치 등급 분류
```
arch_clearance_mm < 8      또는 arch_gap_ratio < 0.20  → "낮은 편" (low)
8 ~ 18                                                 → "보통"   (normal)
> 18                       또는 arch_gap_ratio > 0.40  → "높은 편" (high)
```
> 이 구간값은 **초기 가정치입니다.** 실측 데이터가 쌓이면 반드시 재보정하세요.
> config.py에 상수로 빼두고, 코드에 하드코딩하지 마세요.

#### B6. 교차 검증
```python
delta = abs(foot_length_mm - foot_length_side_mm)
if delta <= 3:   side_confidence = 1.0
elif delta <= 6: side_confidence = 0.7
else:            side_confidence = 0.3  # → "옆면 재촬영" 유도
```

### 3-5. (선택) 정밀 아치 모드 — 발자국 방식

여유가 되면 넣으세요. **상면 파이프라인을 그대로 재사용**하므로 추가 개발량이 매우 적고,
아치 판정은 측면 사진보다 훨씬 정확합니다. 임상에서 쓰는 고전적 방법입니다.

```
1. 발바닥을 살짝 적신 뒤 A4를 밟았다 뗀다
2. 젖은 발자국을 위에서 촬영 → 기존 A4 호모그래피 파이프라인 그대로 통과
3. 접지 면적에서 지수 계산
   Chippaux-Smirak Index = (중족부 최소폭 / 전족부 최대폭) × 100
     < 30%   → 아치 높음
     30~45%  → 보통
     > 45%   → 아치 낮음
```
젖은 자국은 시간이 지나면 마르므로 촬영 타이밍 안내 필요.

### 3-6. 결과 스키마

```python
class TopMeasurement(BaseModel):
    foot_length_mm: float
    ball_width_mm: float
    heel_width_mm: float
    width_ratio: float
    toe_type: Literal["egyptian", "greek", "roman"]
    hallux_valgus_angle_deg: float | None

class SideMeasurement(BaseModel):
    foot_length_side_mm: float
    arch_clearance_mm: float
    arch_gap_length_mm: float
    arch_gap_ratio: float
    instep_height_mm: float
    arch_height_index: float
    arch_grade: Literal["low", "normal", "high"]
    cross_check_delta_mm: float

class FootMeasurement(BaseModel):
    side: Literal["left", "right"]
    top: TopMeasurement
    lateral: SideMeasurement | None      # 측면 촬영은 선택 가능
    confidence: float                    # 0.0 ~ 1.0
    warnings: list[str]

class ScanResult(BaseModel):
    left: FootMeasurement | None
    right: FootMeasurement | None
    asymmetry_mm: float | None
    recommended_size: SizeRecommendation
    scanned_at: datetime
```

- [ ] 아치 등급: 같은 발 5회 촬영 시 등급이 바뀌지 않음 (**mm 정확도보다 이게 더 중요**)

- [ ] 에러 코드 명확 반환: `PAPER_NOT_FOUND` / `FOOT_NOT_FOUND` / `SIDE_REF_NOT_FOUND` / `LOW_CONFIDENCE`
- [ ] 디버그 이미지 8장 정상 저장

## 4. 신발 사이즈 변환

### 4-1. 여유분
```
신발 내부 길이 = 발 길이 + 여유분

구두/드레스   +5 ~ 10mm
스니커즈      +10mm
러닝화        +10 ~ 15mm
등산화        +12 ~ 15mm
샌들          +5mm
```

### 4-2. 표기 변환
```
KR / JP (mondopoint, mm) = round((발길이 + 여유분) / 5) * 5
  예: 253mm + 스니커즈 10mm = 263 → 265
```
> ⚠️ **US/EU/UK 환산식을 Claude Code가 자유롭게 생성하게 두지 마세요.**
> 브랜드마다 기준이 달라서 그럴듯한 틀린 표를 만들어냅니다.
> `data/size_tables.json`에 검증된 표를 넣고 그것만 참조하게 하세요.

### 4-3. 폭 등급 (너비 기반 추정)
```
width_ratio = ball_width_mm / foot_length_mm

< 0.375        좁음 (narrow)
0.375 ~ 0.395  보통 (regular / D)
0.395 ~ 0.415  넓음 (wide / 2E)
> 0.415        매우 넓음 (extra wide / 4E)
```
※ 초기 가정치. 실측 데이터로 재보정 필요. **발볼 둘레 실측이 아니므로 "추정" 표기 필수.**

### 4-4. 아치·발등을 반영한 추천 (측면 데이터 활용)
```
발등 높음 (arch_height_index > 0.37)  → "끈 여유가 있는 모델 / 볼륨 큰 라스트 권장"
아치 낮음 (arch_grade == "low")        → "아치 서포트가 있는 안정화 계열 참고"
아치 높음 (arch_grade == "high")       → "쿠셔닝 위주 모델 참고"
```
모두 "권장"이 아닌 "참고" 표현으로. 진단 표현 금지.

### 4-5. 좌우 비대칭
좌우 길이 차 4mm 이상이면 큰 발 기준으로 추천 + 안내 문구.

## 5. Phase 2 — React Native 앱 (별도 신규 앱)

### 5-1. 스택
```
React Native (Expo)
expo-camera / react-native-vision-camera
expo-sensors               # 자이로 — 상면=수평, 측면=수직 판별
expo-image-manipulator
react-native-svg           # 촬영 가이드 오버레이, 결과 시각화
zustand
expo-sqlite                # 측정 이력
```

### 5-2. 촬영 플로우 (4장)
```
오른발 상면 → 오른발 측면 → 왼발 상면 → 왼발 측면
```
측면 2장은 **건너뛰기 가능**하게 하세요. 4장은 이탈률이 높습니다.
건너뛰면 사이즈만 나오고 아치/발등은 "미측정"으로 표시 + 나중에 추가 촬영 유도.

### 5-3. 화면 구성
```
1. 온보딩 — 준비물(A4 1장), 올바른 자세 vs 잘못된 자세 일러스트
2. 상면 촬영 — A4 비율 SVG 프레임 + 실시간 체크
     · 자이로 수평 ±5도 이내일 때만 셔터 활성화
     · 프레임 평균 밝기 체크
     · A4 4개 코너가 화면 안에 있는지
3. 측면 촬영 — 별도 가이드
     · 자이로 수직 ±5도 이내
     · 화면 하단에 바닥선 가이드라인 표시
     · "발 안쪽을 종이 긴 변에 맞춰 딛으세요" 애니메이션
4. 처리 중 — 단계 표시("종이 인식 → 발 인식 → 측정 → 교차검증")
5. 결과
     · 상면 실루엣 + 치수 오버레이
     · 측면 실루엣 + 아치 곡선 시각화 (이게 앱의 시각적 킬러 요소)
     · 신발 종류별 추천 사이즈 탭
     · 좌우 비교
     · 하단 고정 면책 문구
6. 이력 — 날짜별 기록, 변화 그래프 (아동 성장/부종 추적)
7. 재촬영 유도 — confidence < 0.7 이면 결과 대신 재촬영 화면
```

### 5-4. 사용자 가이드 문구 (그대로 노출)
```
[공통]
1. A4 용지를 단단하고 평평한 바닥에 놓으세요. (카펫 X)
2. 조명을 켜고, 짙은 그림자가 지지 않게 해주세요.
3. 맨발 또는 어두운 색 양말을 신으세요. (흰 양말 X)
4. 체중을 실어 똑바로 서세요.

[상면]
5. 뒤꿈치를 종이 아래 가장자리에 맞추세요.
6. 발 위 40~60cm 높이에서 바닥과 수평으로 촬영하세요.
7. 종이 네 모서리가 모두 보이는지 확인하세요.

[측면]
8. 발 안쪽(엄지 쪽) 라인을 종이의 긴 변에 맞춰 딛으세요.
9. 휴대폰을 바닥에서 10~15cm 높이로 낮추고, 지면과 수직으로 세우세요.
10. 발에서 약 1m 떨어져서, 종이 긴 변이 화면 가로로 꽉 차게 촬영하세요.
```

**체중 부하가 중요한 이유:** 서 있을 때 발은 앉아 있을 때보다 3~7mm 길어집니다.
신발은 체중이 실린 상태로 신으므로 반드시 선 채로 측정합니다.
또한 저녁에는 붓기 때문에 아침보다 크게 나옵니다 — 앱에서 안내 표시.

## 7. Claude Code 첫 작업 지시 (복붙용)

```
이 SPEC.md를 읽고 Phase 0만 구현해줘. React Native 앱은 아직 만들지 마.

engine/ 폴더에 파이썬 CV 파이프라인을 만들어줘.

[요구사항]
1. 3-3 파이프라인 A(상면)와 3-4 파이프라인 B(측면)를 각각 별도 모듈로 구현.
   6번의 폴더 구조를 그대로 따라줘.
2. 각 단계마다 디버그 이미지를 저장하고, 실패 시 어느 단계에서 왜 실패했는지
   에러 코드와 한글 메시지를 함께 반환.
3. 3-4의 B6 교차검증(상면/측면 발 길이 비교)을 반드시 구현.
4. 모든 임계값과 상수는 config.py 한 곳에 모아줘. 코드 안에 숫자를 직접 쓰지 마.
   (내가 나중에 실측 데이터로 보정할 예정)
5. cli.py로 아래가 동작해야 함:
     python cli.py --top samples/right_top.jpg --side-img samples/right_side.jpg \
                   --foot right --debug
   측면 인자는 선택이어야 하고, 없으면 상면 결과만 출력.
6. 아직 실제 사진이 없으니 tests/make_synthetic.py를 먼저 만들어줘.
   - A4 위에 발 모양 실루엣이 있는 상면 합성 이미지
   - 아치 곡선이 있는 측면 합성 이미지 (아치 높이를 파라미터로 조절 가능하게)
   - 정답 치수를 JSON으로 같이 저장 (회귀 테스트용)
   이걸로 파이프라인을 먼저 검증하고, 그 다음에 내가 실제 사진을 찍어서 넣을게.
7. 코드에 한글 주석을 달아줘. 나는 비개발자야.
   특히 config.py의 각 상수에는 "이 값을 올리면/내리면 어떻게 되는지"를 주석으로 적어줘.

[진행 방식]
한 번에 다 만들지 말고, 이 순서로 하나씩 완성하고 나에게 결과를 보여줘:
  (1) tests/make_synthetic.py + config.py + schemas.py
  (2) 파이프라인 A (상면) 전체 + 합성 이미지로 검증
  (3) 파이프라인 B (측면) 전체 + 합성 이미지로 검증
  (4) 교차검증 + cli.py 통합

각 단계마다 실제로 실행해서 디버그 이미지와 측정 결과를 보여줘.
```
