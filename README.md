## 폴더 구조

```
handoff/     ← 인수인계 기준본. 새 개발자는 여기부터
  DATA_CONTRACT.md   센서 ↔ 앱 데이터 규격. 실제 계약 지점
  HANDOFF.md         무엇이 진짜고 무엇이 가짜인지
  index.html + js/   앱 프로토타입 (더블클릭하면 바로 열림)

docs/        ← GitHub Pages 배포본. handoff/ 와 동일한 내용
             https://heonchris.github.io/claude-test-project/

hardware/    ← 아두이노 펌웨어
  step1_fsr_test/        센서 1개 포화 테스트
  step2_bluetooth_test/  블루투스 모듈 확인 + 무선 전송

ios/         ← Xcode 래퍼 (WKWebView). 아이폰 설치용
app/         ← 초기 단일 파일 프로토타입 (보관용. handoff/ 가 최신)
.feedback/   ← 자체 점검 기록
```

`handoff/` 와 `docs/` 는 **같은 내용의 복제본**입니다.
`handoff/` 를 고치면 `docs/` 에도 반영해야 배포본이 따라갑니다.

## 알려진 문제

**34바이트 패킷이 BLE 기본 전송 단위(20바이트)를 넘습니다.**
HM-10·AT-09 같은 흔한 모듈은 한 번에 20바이트까지만 보내므로
34바이트가 20 + 14 로 쪼개져 도착합니다. 그런데 `js/11-ble.js` 의
`handlePacket()` 은 **정확히 34바이트**가 아니면 버리므로, 이대로는
모든 패킷이 버려집니다. 8채널 연동 전에 아래 중 하나를 정해야 합니다.

- 수신 측에서 조각을 모아 헤더(0xA5) 기준으로 재조립
- 8채널씩 두 패킷으로 분할 (패킷당 18바이트)
- MTU 협상을 지원하는 모듈·칩으로 교체 (ESP32 등)

자세한 내용은 `handoff/DATA_CONTRACT.md` 2절.
