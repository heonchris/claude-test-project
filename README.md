## 하드웨어 점검 시 꼭 기억할 것

**막히면 핀을 옮겨 보세요.** 블루투스 연동이 끝까지 안 되던 원인이
**아두이노 디지털 3번 핀의 고장**이었습니다. 배선 순서(12조합)·통신 속도
(6가지)·모듈·앱을 모두 검증해 정상임을 증명한 뒤에야, 핀을 4·5번으로
옮기자 즉시 동작했습니다.

코드로는 찾을 수 없는 고장이고, 증상은 '한쪽 방향만 안 됨' 으로 나타납니다.
진단 순서는 `hardware/step2_bluetooth_test/README.md` 에 정리했습니다.
현재 모든 스케치는 **디지털 4번(모듈 TXD) · 5번(모듈 RXD)** 를 씁니다.

## 해결된 문제 (2025-10)

실기기 연동을 막고 있던 두 가지를 고쳤습니다. 둘 다 `js/11-ble.js` 입니다.

**① UUID 불일치** — 앱이 `FFF0/FFF1` 만 찾았는데, 시중 모듈(HM-10·AT-09)은
공장 기본값이 `FFE0/FFE1` 입니다. 기기 선택 창에 아예 나오지 않았습니다.
이제 두 가지를 모두 시도해 먼저 잡히는 쪽을 씁니다.

**② 20바이트 분할** — BLE 는 한 번에 20바이트까지만 보내므로 34바이트가
20 + 14 로 쪼개져 도착하는데, 옛 코드는 정확히 34바이트가 아니면 버렸습니다.
이제 조각을 모아 헤더(`0xA5`) 기준으로 재조립합니다.

## 다음 구조 결정 — 발마다 독립 모듈

인솔은 **발마다 아두이노 + 블루투스 모듈 1개씩**, 폰이 2개에 동시 연결하는
구조로 간다. 패킷이 발당 19바이트가 되어 BLE 20바이트 분할 문제와
9600 baud 로 30Hz 가 안 되는 문제가 함께 사라진다.
자세한 내용과 주의점은 `handoff/DATA_CONTRACT.md` 2-2절.

보드는 **나노**로. 우노는 아날로그 핀이 6개뿐이라 발당 8채널이 안 된다.

## 남은 제약

**9600 baud 로는 30Hz 가 안 나옵니다.** 34바이트 × 30Hz = 1,020 B/s 인데
9600 baud 의 한도는 약 960 B/s 입니다. 브링업은 10Hz 로 하고, 30Hz 가
필요해지면 모듈 UART 속도를 `AT+BAUD` 로 올려야 합니다.

**패킷에 체크섬이 없습니다.** 데이터 안의 `0xA5` 가 패킷 경계와 겹치면
한 번 어긋날 수 있습니다(순번으로 자동 복구). 8채널로 가기 전에 추가 권장.

자세한 내용은 `handoff/DATA_CONTRACT.md` 2절.
