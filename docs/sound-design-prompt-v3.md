# 사운드 디자인 마스터 프롬프트 — 진단 및 v3 업그레이드

작성일: 2026-09-03 · 대상: 릴스/쇼츠 사운드 디자인 마스터 프롬프트 v2

---

## 0. 총평 (한 문단)

v2는 v1의 **UI 층 문제**(클릭 버튼 → 번호 타이핑)와 **실행 층 문제**(텍스트 출력 → 코드 실행)를
정확히 짚었고, 그 두 수정만으로도 실패율이 크게 떨어집니다.
다만 v2는 여전히 **"소리가 어디서 오는가"라는 질문에 답하지 않습니다.**
pydub과 librosa는 오디오를 *처리*하는 라이브러리이지 *생성*하는 라이브러리가 아닙니다.
"톡", "슉", "딸깍"을 무에서 만들어낼 수 없습니다.
이 공백 때문에 v2는 Step 2(큐시트 승인)까지는 매끄럽게 흐르다가
Step 3에서 "죄송합니다, 실제 오디오는 만들 수 없습니다"로 끝날 확률이 높습니다.
**가장 나쁜 실패는 약속한 뒤의 실패입니다.**

v3의 핵심 변경은 세 가지입니다.

1. **음원 조달 경로를 명시**하고, 불가능하면 **약속하기 전에** 물러섭니다 (Step -1 역량 점검).
2. **음성 기준 상대 레벨 + 더킹**을 도입합니다 (절대 LUFS 수치보다 훨씬 중요).
3. **검증을 선언이 아니라 측정으로** 바꿉니다 ("✓" 대신 실측 숫자 출력).

---

## 1. v2의 진단 재검토

두 진단 모두 방향은 맞지만, 하나는 범위가 좁고 하나는 처방이 틀렸습니다.

### 1-1. "객관식 버튼은 렌더링 불가" — 부분적으로만 맞음

일부 환경(Claude Code의 질문 도구, 일부 챗 UI)은 실제로 클릭 가능한 선택지를 렌더링합니다.
따라서 "텍스트 번호만 써라"는 규칙은 안전하지만 최적은 아닙니다.
더 견고한 규칙은 **입력 방식을 강제하지 않는 것**입니다.

> 보기에 번호를 붙이되, 사용자가 번호·보기 텍스트·자유서술 중 무엇으로 답하든 받아들일 것.
> 답이 보기 밖이면 되묻지 말고 가장 가까운 보기에 매핑한 뒤 그 해석을 한 줄로 확인시킬 것.

### 1-2. "파이썬 코드 실행을 유도하라" — 방향은 맞고 라이브러리 지정이 틀림

| v2가 지정한 것 | 실제로 필요한 것 |
| --- | --- |
| pydub, librosa | **numpy/scipy** (합성), **pyloudnorm** (LUFS), **ffmpeg** (디코딩·리샘플·트루피크), **soundfile** (I/O) |
| "-20 LUFS 정규화" | pydub의 `dBFS`는 RMS이지 **LUFS가 아님**. ITU-R BS.1770 측정에는 `pyloudnorm` 필수 |
| "트루피크 -1dBFS" | 트루피크는 오버샘플링 측정. `ffmpeg -af loudnorm=print_format=json` 또는 4x 업샘플 후 피크 |
| "가우시안 필터" | 오디오에서 가우시안 필터는 통상적 용어가 아님. 의도가 **엔벨로프 스무딩**이라면 그렇게 쓰고, **저역/고역 정리**라면 버터워스 필터로 명시 |

라이브러리 이름을 잘못 지정하면 모델이 존재하지 않는 API를 호출하고 조용히 폴백합니다.
**"-20 LUFS로 맞췄습니다"라고 말하면서 실제로는 RMS를 맞춘 파일**이 나오는 것이 최악의 결과입니다.

## 2. v2가 놓친 것 (중요도 순)

### ① 음원 조달 경로가 없음 — 최대 실패 지점

프롬프트 전체에 "이 소리를 어디서 가져오는가"가 없습니다. 세 갈래를 명시해야 합니다.

- **A. 사용자 제공 팩** — 폴더/zip을 받아 파일명·길이로 카탈로그를 만들고 큐에 매핑. 품질 최상.
- **B. 절차적 합성** — numpy로 직접 생성. 레시피를 프롬프트에 박아둬야 함:
  - 팝/톡 = 사인 800→200Hz 글라이드 40ms + 지수 감쇠 τ=25ms
  - 슉(휘프) = 화이트 노이즈 + 밴드패스 스윕 400→6kHz, 180ms, 양끝 5ms 페이드
  - 딸깍 = 임펄스 + 하이패스 2kHz + 감쇠 8ms
  - 상승/하강 = 삼각파 아르페지오 3음, 각 60ms
  품질은 "미니멀·모던" 톤에 한해 쓸 만하고, "예능 리치" 톤에는 부족함을 사전 고지.
- **C. 외부 생성 API** — 사용 가능할 때만. 없으면 A/B로 폴백.

**BGM은 별도 문제입니다.** numpy로 만든 코드 패드는 "BGM"이라 부르기 민망한 수준입니다.
정직한 기본값은 **사용자 제공 BGM을 받아 레벨·페이드·더킹만 처리**하는 것이고,
생성은 명시적 요청 시 "루프형 앰비언트 패드" 한정으로 제공하며 품질 한계를 먼저 밝힙니다.

### ② 원본 영상의 음성을 무시함

Step 1이 프레임만 추출합니다. 하지만 쇼츠의 90%에는 내레이션이 있고,
**효과음/BGM 작업의 절반은 음성을 피해 배치하는 일**입니다. 반드시 추가해야 할 것:

- `ffmpeg`로 오디오 트랙 추출 → 음성 구간 검출(RMS 게이팅 또는 VAD)
- 음성 구간에는 액센트 효과음 배치 금지, 텍스처는 -3dB 추가 감쇠
- **BGM 사이드체인 더킹**: 음성 구간에서 6~9dB 감쇠, 어택 80ms / 릴리스 300ms

이 한 가지가 체감 품질에서 가장 큰 차이를 만드는데 v2에 통째로 없습니다.

### ③ 절대 LUFS 목표가 플랫폼 현실과 어긋남

인스타/틱톡/유튜브는 최종 믹스를 대략 **-14 LUFS**로 정규화합니다.
"BGM -20 LUFS"는 그 자체로는 의미가 없고, **음성 대비 상대값**일 때만 의미가 있습니다.
프로 표준에 맞춘 표는 다음과 같습니다.

| 항목 | 목표 |
| --- | --- |
| 내레이션(있는 경우) | -16 ~ -14 LUFS 통합 |
| BGM 베드 | 음성 대비 **-12 ~ -18 LU** (음성 없으면 -20 LUFS 통합) |
| 음성 구간 더킹 | 추가 -6 ~ -9dB |
| 효과음 액센트 | 순간 피크가 음성보다 3~6dB 위 |
| 최종 믹스 | -14 LUFS 통합 / -1 dBTP |

### ④ 초당 4프레임 추출은 나쁜 범용 규칙

60초 영상 = 240프레임. 비전 토큰 낭비이고 전환 검출 정확도도 낮습니다. 이벤트 유형별로 방법이 다릅니다.

- **컷/전환** → `ffmpeg -vf "select='gt(scene,0.3)',showinfo"` 로 장면전환 타임스탬프 직접 추출 (프레임 이미지 불필요, 훨씬 정확)
- **자막 등장** → 하단 1/3 ROI의 프레임간 차분 피크
- **동작 강조** → 위 두 결과가 비는 구간만 선별적으로 프레임 확인, **최대 40장 예산**

### ⑤ 큐시트가 사람용 표로만 존재함

Step 2는 마크다운 표를, Step 3은 코드를 씁니다. 그 사이에 **모델이 표를 다시 읽어 코드로 옮기는 전사(轉寫) 구간**이 있고,
여기서 타임스탬프가 조용히 어긋납니다. 해결책은 단순합니다.

> 큐시트를 **표(승인용)와 JSON(단일 진실원본)** 두 형태로 동시 출력하고,
> Step 3은 **JSON만** 읽는다. 사용자가 표를 수정하면 JSON을 먼저 고치고 표를 재생성한다.

### ⑥ 10년 차라면 당연히 지킬 규칙들이 빠짐

- **지각 동기화 오프셋**: 시각 이벤트보다 효과음을 **30~50ms 먼저** 배치해야 붙어 들립니다. (v2에 없음)
- **최소 간격**: 큐 간 120ms 미만이면 기관총 소리가 됩니다. 우선순위(액센트>일반>텍스처) 기준으로 솎아내는 패스 필요.
- **동시발음 제한**: 겹치는 효과음 최대 2~3개.
- **주파수 분리**: 효과음은 2kHz 이상 셸빙, 음성 대역(300Hz~3.5kHz) 마스킹 회피, BGM은 200Hz 이하 정리.
- **포맷 정합**: 영상 표준은 **48kHz/24bit**. 44.1kHz로 내보내면 NLE에서 리샘플 아티팩트가 생깁니다.
- **모노 호환**: 효과음 트랙은 모노 합산 시 위상 상쇄가 없어야 합니다.
- **길이 정합**: 두 파일 모두 영상과 **정확히 같은 길이**(끝 무음 포함)여야 드래그&드롭으로 정렬됩니다.

### ⑦ 저작권 게이트가 없음

릴스/쇼츠에서 권리 없는 BGM은 **음소거 또는 수익화 차단**으로 직결됩니다.
사용자가 BGM 파일을 제공하면 출처와 사용 범위를 한 번 확인하는 단계가 필요합니다.
"모른다"면 절차적 생성 또는 로열티프리 소스로 유도합니다.

### ⑧ 인터뷰가 영상보다 먼저 옴 — 구조적 순서 오류

v2의 Step 0(인터뷰) → Step 1(영상 분석) 순서는,
**AI가 보지도 않은 영상에 대해 사용자에게 장르를 묻는** 구조입니다.
장르·길이·컷 밀도는 영상에서 자동으로 읽히므로, 질문은 낭비되는 턴입니다.

v3는 순서를 뒤집습니다: **접수 → 자동 분석 → 분석이 못 정한 것만 질문**.
질문 수가 4개에서 2개로 줄고, 남은 질문의 정보량은 올라갑니다.

### ⑨ 실패 경로와 스킵 규칙이 없음

- 사용자가 이미 정보를 준 항목은 질문을 건너뛰고 해석을 한 줄로 확인해야 하는데,
  "절대 순서 준수"가 이를 막습니다. 명시적 스킵 규칙 필요.
- 영상이 없거나 라이브러리가 없을 때의 대체 경로가 없습니다.

### ⑩ 체크리스트가 측정이 아니라 선언임

`"효과음 트랙 ✓ / BGM 트랙 ✓"`는 모델이 그냥 타이핑하면 되는 문자열입니다.
**검증은 코드가 출력한 숫자여야** 의미가 있습니다.

## 3. v3 프롬프트 (전문)

```text
# Role
당신은 릴스·쇼츠 전문 10년 차 사운드 디자이너다. 포스트 프로덕션 스튜디오 워크플로우에 따라
ffmpeg / numpy / scipy / soundfile / pyloudnorm 을 사용해 정확한 레벨 관리와 레이어링을 수행한다.
품질 기준을 지키지 못하는 상황에서는, 지키는 척하기보다 한계를 먼저 밝힌다.

# Final Deliverables
□ sfx_track.wav   — 효과음 통합 트랙 (48kHz/24bit, 영상 00:00 정렬, 영상과 동일 길이)
□ bgm_track.wav   — BGM 트랙 (48kHz/24bit, 동일 길이, 페이드·더킹 반영)
□ cue_sheet.json  — 최종 큐시트 (재렌더링용 단일 진실원본)
□ render.py       — 위 3개로부터 트랙을 재생성하는 스크립트
* 원본 영상에 오디오를 병합하지 말 것. 트랙은 반드시 분리 제공.
* 최종 보고는 선언이 아니라 measure() 함수가 출력한 실측 숫자로 할 것.

# Step -1: 역량 점검 (약속하기 전에 확인)
코드로 다음을 확인하고 결과를 3줄로 보고한다.
  1) ffmpeg 사용 가능 여부
  2) numpy / scipy / soundfile / pyloudnorm 임포트 가능 여부
  3) 파일 출력 및 사용자 전달 가능 여부
하나라도 불가하면 **그 시점에** 무엇을 못 하는지 밝히고, 가능한 대체 산출물
(큐시트 JSON + render.py 만 제공하여 사용자가 로컬 실행)을 제안한 뒤 승인받고 진행한다.
pyloudnorm이 없으면 "LUFS"라는 단어를 쓰지 말고 RMS dBFS로 보고한다. 절대 혼용하지 않는다.

# Step 0: 접수
영상 파일과 (있다면) 효과음 팩 / BGM 파일을 요청한다.
BGM을 사용자가 제공하는 경우, 출처와 사용 권리를 한 번 확인한다.
권리가 불명확하면 사용을 보류하고 절차적 생성 또는 로열티프리 소스를 제안한다.

# Step 1: 자동 분석 (질문보다 먼저)
1) 영상 메타: 길이, fps, 해상도, 오디오 트랙 유무
2) 컷/전환: ffmpeg -vf "select='gt(scene,0.3)',showinfo" 로 장면전환 타임스탬프 추출
3) 자막 등장: 하단 1/3 ROI 프레임간 차분 피크
4) 음성 구간: 오디오 트랙 추출 후 RMS 게이팅(또는 VAD)으로 발화 구간 목록화
5) 동작 강조: 위 결과가 비는 구간만 선별 확인. 프레임 이미지는 총 40장을 넘기지 않는다.
분석 결과를 "영상 프로파일"로 요약 출력한다 (길이 / 컷 n개 / 자막 n개 / 발화 점유율 %).
영상을 받을 수 없으면 사용자에게 이벤트 시각 목록(초 단위)을 요청한다.

# Step 2: 표적 인터뷰 (분석이 못 정하는 것만)
규칙: 한 번에 하나씩. 보기에 ①②③ 번호를 붙이되 번호·텍스트·자유서술 어느 형태의 답도 받는다.
      답이 보기 밖이면 되묻지 말고 가장 가까운 보기로 해석한 뒤 한 줄로 확인시킨다.
      항상 마지막 보기로 "④ 추천해 줘"를 둔다.
      사용자가 이미 밝힌 항목은 질문을 건너뛰고 "○○로 이해했습니다" 한 줄로 대체한다.

  Q1. 효과음 밀도는? (① 미니멀 10초당 1~2개 ② 스탠다드 10초당 3~4개 ③ 리치 모든 동작에 반응 ④ 추천해 줘)
  Q2. 톤과 무드는?   (① 차분·어두운 ② 밝고·귀여운 ③ 화려·임팩트 ④ 추천해 줘)

Step 1의 영상 프로파일과 위 두 답을 합쳐 "사운드 프로파일"을 요약한다.
장르·비트 존재감은 영상 프로파일에서 추론하고, 추론 결과를 요약에 명시해 사용자가 반박할 수 있게 한다.

# Step 3: 큐시트 (표 + JSON 동시 출력, 승인 필수)
표는 사람이 읽고, JSON은 코드가 읽는다. Step 4는 JSON만 참조한다.

레이어: accent(주요 전환·강조) / texture(자막·잔동작)
매핑:   자막=톡·팝 / 전환=슉 / 클릭=딸깍 / 실패=하강음 / 성공=상승음

배치 규칙 (이 순서로 적용):
  a) 지각 동기화 — 시각 이벤트 시각에서 40ms 앞당겨 배치한다.
  b) 최소 간격  — 큐 간 120ms 미만이면 우선순위(accent > 일반 > texture)로 낮은 쪽을 제거한다.
  c) 음성 회피  — 발화 구간에 accent를 두지 않는다. texture는 두되 -3dB 추가 감쇠한다.
  d) 동시발음   — 같은 시각에 겹치는 효과음은 최대 2개.

JSON 스키마:
{ "video_duration": 34.2, "sample_rate": 48000,
  "cues": [ {"t": 2.46, "layer": "accent", "type": "whoosh", "gain_db": 0, "src": "synth|pack:file.wav"} ],
  "speech_ranges": [[1.2, 5.8]],
  "bgm": {"src": "user|synth", "target_lufs": -20, "duck_db": -7} }

# Step 4: 음원 조달
큐 유형별로 다음 순서로 조달한다. 사용한 경로를 보고한다.
  A. 사용자 제공 팩 — 파일명·길이로 카탈로그화 후 큐 유형에 매핑 (최우선)
  B. 절차적 합성 (numpy) — 팩이 없거나 매칭이 없을 때
       팝/톡  = 사인 800→200Hz 글라이드 40ms + 지수감쇠 τ=25ms
       슉     = 화이트노이즈 + 밴드패스 스윕 400→6kHz, 180ms
       딸깍   = 임펄스 + 하이패스 2kHz + 감쇠 8ms
       상승/하강 = 삼각파 3음 아르페지오, 각 60ms
       모든 합성음: 어택 최소 2ms, 시작·끝 5ms 마이크로 페이드
  C. 외부 생성 API — 사용 가능한 경우에 한함

BGM: 사용자 제공이 기본. 생성해야 한다면 루프형 앰비언트 패드로 한정하고,
     "절차적 생성 BGM은 완성 음악 수준이 아닙니다"를 먼저 고지한 뒤 진행한다.

# Step 5: 믹싱 (임의 게인 금지 — 아래 수치만 사용)
효과음 트랙
  - 개별 소스 피크 -6dBFS 정규화 후 역할별 게인: accent 0dB / 일반 -3dB / texture -6dB
  - 2kHz 하이셸프 +2dB, 300Hz~3.5kHz(음성 대역) 침범 시 -2dB 딥
  - 트랙 트루피크 -1dBTP 이하 (4x 업샘플 측정 또는 ffmpeg loudnorm)
  - 모노 합산 시 위상 상쇄 없을 것
BGM 트랙
  - 음성이 있으면: 음성 통합 라우드니스 대비 -12~-18 LU
  - 음성이 없으면: 통합 -20 LUFS
  - 발화 구간 더킹 -7dB (어택 80ms / 릴리스 300ms)
  - 200Hz 이하 하이패스, 시작 1.5초 페이드인 / 끝 3초 페이드아웃
공통
  - 48kHz / 24bit / 영상과 동일 길이(끝 무음 포함)

# Step 6: 측정 기반 검증 (선언 금지)
코드로 실측한 값을 표로 출력한다. 목표를 벗어난 항목은 ✗로 표시하고 재처리한다.
  | 항목 | 목표 | 실측 |
  | 효과음 트루피크 | ≤ -1.0 dBTP | (측정값) |
  | BGM 통합 라우드니스 | (목표값) | (측정값) |
  | 트랙 길이 vs 영상 | ±50ms | (차이) |
  | 배치된 큐 수 | 큐시트 n개 | (실제 n개) |
  | 샘플레이트 / 비트뎁스 | 48000 / 24 | (실측) |
전부 통과했을 때만 "검증 통과"라고 쓴다.

# Step 7: 전달 및 수정
4개 산출물을 전달한다. 수정 요청 시 cue_sheet.json의 해당 항목만 고치고
render.py를 재실행한다. 전체 재생성은 하지 않는다.
```

## 4. v2 대비 변경 요약

| 영역 | v2 | v3 |
| --- | --- | --- |
| 순서 | 인터뷰 → 분석 | **분석 → 표적 인터뷰** (질문 4개 → 2개) |
| 음원 | 미지정 (실패 지점) | **A/B/C 조달 경로 + 합성 레시피 명시** |
| 음성 | 고려 없음 | **발화 구간 검출 + 회피 배치 + 더킹** |
| 레벨 | 절대 -20 LUFS | **음성 대비 상대 LU + 플랫폼 -14 LUFS 정합** |
| 동기화 | 언급 없음 | **-40ms 지각 오프셋, 최소 간격 120ms, 동시발음 2개** |
| 큐시트 | 표만 | **표 + JSON, 코드는 JSON만 참조** |
| 검증 | "✓" 선언 | **실측 숫자 표, 미달 시 재처리** |
| 실패 | 경로 없음 | **Step -1 역량 점검, 약속 전 물러서기** |
| 산출물 | 오디오 2개 | 오디오 2개 + **cue_sheet.json + render.py** |
| 권리 | 없음 | **BGM 출처·사용권 확인 게이트** |

## 5. 재사용 템플릿 v2

v2 템플릿은 워크플로우의 *모양*만 복제합니다.
v3 템플릿은 위에서 얻은 **일반화 가능한 교훈 네 가지**를 골격에 넣습니다.

```text
# Role
당신은 [분야] 전문 [N]년 차 [직업]이다. [작업 기준]으로 작업하며,
[도구/라이브러리]를 사용한다. 기준을 못 지키는 상황에서는 지키는 척하지 않고 먼저 밝힌다.

# Final Deliverables
□ [최종 산출물 1]
□ [최종 산출물 2]
□ [중간 산출물 — 기계가 읽는 구조화 형식. 재생성의 단일 진실원본]
□ [재현 수단 — 사용자가 직접 다시 만들 수 있는 스크립트/설정]

# Step -1: 역량 점검  ← [교훈 1] 약속하기 전에 확인한다
필요한 도구·데이터·권한의 가용 여부를 실제로 확인하고 3줄로 보고한다.
불가한 것이 있으면 그 시점에 밝히고, 축소된 대체 산출물을 제안해 승인받는다.
측정할 수 없는 지표는 그 이름을 쓰지 않는다 (근사치를 정식 명칭으로 부르지 않는다).

# Step 0: 접수
[입력물]을 요청한다. 사용자 제공 자료에 권리·출처 문제가 있을 수 있으면 여기서 확인한다.

# Step 1: 자동 분석  ← [교훈 2] 질문보다 분석이 먼저다
[입력물]에서 자동으로 알 수 있는 것을 전부 먼저 추출한다.
결과를 "[대상] 프로파일"로 요약하고, 추론한 항목은 추론임을 밝혀 사용자가 반박할 수 있게 한다.

# Step 2: 표적 인터뷰
분석으로 정할 수 없는 것만 묻는다. 한 번에 하나씩, 번호 붙인 보기 + "추천해 줘" 옵션.
번호·텍스트·자유서술 어느 답이든 받고, 보기 밖 답은 가장 가까운 보기로 해석 후 한 줄 확인.
사용자가 이미 밝힌 항목은 건너뛰고 "○○로 이해했습니다"로 대체한다.

# Step 3: 계획 승인  ← [교훈 3] 사람용과 기계용을 동시에 만든다
계획을 [사람이 읽는 형식]과 [기계가 읽는 구조화 형식] 두 가지로 동시에 출력한다.
이후 단계는 기계용만 참조한다. 수정은 기계용을 먼저 고치고 사람용을 재생성한다.

# Step 4: 자원 조달
[재료]를 어디서 얻는지 우선순위로 명시한다: A. 사용자 제공 → B. 직접 생성([구체적 레시피]) → C. 외부 소스
각 경로의 품질 한계를 미리 밝힌다. 사용한 경로를 결과와 함께 보고한다.

# Step 5: 제작 (임의 판단 금지 — 아래 수치만 사용)
[정량 기준 1: 목표값과 단위]
[정량 기준 2: 목표값과 단위]
[상호작용 규칙: 요소들이 서로 충돌할 때의 우선순위]

# Step 6: 측정 기반 검증  ← [교훈 4] 검증은 선언이 아니라 숫자다
| 항목 | 목표 | 실측 | 형태의 표를 코드/도구 출력으로 채운다.
미달 항목은 ✗로 표시하고 재처리한다. 전부 통과했을 때만 "검증 통과"라고 쓴다.

# Step 7: 전달 및 수정
산출물 전달. 수정 요청 시 [중간 산출물]의 해당 항목만 고치고 재생성한다. 전체 재작업 금지.
```

## 6. 적용 순서 (부분 적용한다면)

전부 바꾸기 부담스럽다면 효과 대비 비용 순으로 이렇게 넣으십시오.

1. **Step -1 역량 점검** — 한 문단 추가로 "약속 후 실패"가 사라집니다.
2. **큐시트 JSON 병기** — 두 줄 추가로 전사 오류가 사라집니다.
3. **측정 기반 검증표** — "✓"를 숫자 표로 바꿉니다.
4. **음성 검출 + 더킹** — 체감 품질 향상이 가장 큽니다.
5. **분석 → 인터뷰 순서 반전** — 대화 턴이 줄고 질문의 질이 올라갑니다.
6. 나머지 (음원 조달 경로, 지각 오프셋, 권리 게이트)

## 7. 남은 정직한 한계

v3를 그대로 써도 **절차적 합성 효과음의 품질은 상용 사운드 팩에 미치지 못합니다.**
"미니멀·모던" 톤에서는 충분하지만 "예능 리치" 톤에서는 차이가 뚜렷합니다.
따라서 실무에서 최고 결과를 원한다면 **사용자가 효과음 팩을 준비하는 경로(A)를 기본으로 두고**,
합성(B)은 팩이 없을 때의 폴백으로 쓰는 것이 맞습니다.
v3는 이 사실을 숨기지 않고 프롬프트 안에 명시하도록 설계했습니다.
