## 라운드 1

### 🔴 고침 — 수정 화면에서 저장만 눌러도 날짜가 옮겨졌다

**증상**
어제 찍은 사진을 "오늘 기록"으로 남겨둔 뒤, 그 기록을 열어 메모만 고치고 저장하면
**기록이 조용히 어제로 옮겨갔다.**

**원인**
`useTakenDate`(그날 기록으로 남기기 스위치)의 초기값이 항상 `true`였다.
새로 만들 때는 맞지만, **이미 저장된 기록에는 사용자가 이전에 내린 결정이 있다.**

**고친 방법**
`app/add/meal.tsx` — 기존 기록을 불러올 때 `setUseTakenDate(false)`.
저장된 날짜를 존중하고, 사용자가 스위치를 직접 켰을 때만 옮긴다.

---

### 🔴 고침 — 시각을 입력하고 바로 저장하면 입력값이 무시됐다

**증상**
`먹은 시각`에 `08:30`을 치고 키보드를 내리지 않은 채 `저장`을 누르면
입력한 시각이 반영되지 않고 예전 값으로 저장됐다.

**원인**
시각 반영을 `onBlur`에서만 했다. 저장 버튼을 바로 누르면 blur가 먼저 걸린다는 보장이 없다.

**고친 방법**
저장 직전에 입력창의 문자열을 한 번 더 해석한다.

```ts
const typed = timeText ? applyTimeString(takenAt ?? fromKey(date), timeText) : null;
const when = typed ?? takenAt ?? new Date();
```

공복 타이머가 이 값에서 시작하므로, 틀리면 화면 전체가 틀어지는 자리였다.

---

### 🟡 고침 — 며칠 기록을 안 하면 "80시간 공복"이라고 나왔다

**증상**
3일간 앱을 안 열면 공복 카드가 `80시간 12분`을 띄웠다.

**왜 문제인가**
사실이 아니다. 굶은 게 아니라 **기록을 안 한 것**이다.
게다가 큰 숫자를 들이미는 건 원칙 3(평가하지 않는다)과도 어긋난다.

**고친 방법**
마지막 식사가 **36시간**을 넘으면 숫자를 감추고 한 줄로 바꾼다.

> 마지막 식사 기록이 하루가 넘었어요. 한 끼 남기면 거기서부터 다시 세어드릴게요.

---

### 🟢 고침 — 주간 타임라인의 시각 눈금이 어긋나 있었다

`0시 / 6시 / 12시 / 18시` 라벨이 요일 라벨 너비만큼 왼쪽으로 밀려,
막대의 실제 위치와 맞지 않았다. 헤더를 트랙과 같은 구조로 감쌌다.

---

## 확인했고 문제가 없던 것

| 본 것 | 결과 |
|---|---|
| 자정을 넘긴 공복 계산 | 정상. 날짜가 아니라 시각 차이로 계산한다 |
| 기존 DB 마이그레이션 | 정상. 열이 없을 때만 추가하고 옛 기록은 저장 시각으로 채운다 |
| 예전에 내보낸 백업 JSON 복원 | 정상. `taken_at`이 없으면 `created_at`으로 채운다 |
| 사진 없이 저장한 기록 | 정상. 저장 시각이 공복 시작점이 된다 |
| 공복이 달성률에 섞이지 않는지 | 정상. 고양이 벽 높이에 영향을 주지 않는다 |
| 미래 시각을 입력했을 때 | 정상. 음수는 0으로 막는다 |
| 타입 검사 · iOS 번들 빌드 | 통과 |

## 코드가 아니라 사용 방식에서 주의할 것

### ⚠️ 번들 ID를 바꾸면 기록이 전부 사라진다

`Bundle Identifier`(현재 `com.cathealth.app.seungheon`)는 아이폰이 앱을 구분하는 이름이다.
이걸 바꾸면 **아이폰은 완전히 다른 앱으로 인식**해서, 기존 앱의 사진과 기록에 접근할 수 없다.

- 7일마다 재설치하는 것: 기록 유지됨 ✅
- 새 버전으로 업데이트하는 것: 기록 유지됨 ✅
- **번들 ID를 바꾸는 것: 기록 사라짐** ❌
- 앱을 삭제하는 것: 기록 사라짐 ❌

한 번 정한 뒤로는 건드리지 않는 게 좋다.

## 라운드 2

### 🔴🔴 고침 — 재설치하면 사진이 전부 안 보이게 될 상황이었다

**증상 (아직 겪지 않았지만 다음 재설치 때 터질 문제)**
7일 만료로 앱을 다시 설치하면, 그때까지 찍은 **모든 식단 사진이 빈 칸으로 바뀐다.**
기록과 시각은 남지만 사진만 사라진다.

**원인**
사진 위치를 이런 식으로 통째로 저장하고 있었다.

```
file:///var/mobile/Containers/Data/Application/9F3C.../Documents/photos/1756-ab12.jpg
                                                 ^^^^^^^ 여기가 매번 바뀐다
```

가운데 긴 영문/숫자는 **아이폰이 앱마다 붙이는 주소**인데,
iOS는 **앱을 다시 설치할 때마다 이 주소를 새로 만든다.**
그래서 예전 주소를 적어두면 다음 설치 때 "그런 곳 없음"이 된다.

일반적인 앱은 재설치가 드물어서 잘 안 드러나지만,
이 앱은 무료 계정 제한 때문에 **7일마다 재설치**하는 구조라 정면으로 부딪히는 문제였다.

**고친 방법**
DB에는 **파일 이름만** 저장한다 (`1756-ab12.jpg`).
화면에 띄울 때 그때그때 현재 앱 주소와 합친다.

- `lib/photos.ts` — 저장은 이름만, `resolvePhotoUri()`가 볼 때 주소를 만든다
- `db/index.ts` — 이미 저장된 예전 주소들은 앱을 켤 때 자동으로 이름만 남기게 줄인다
- 이미 찍어두신 사진은 그대로 보입니다. 따로 하실 일 없습니다

---

### 🔴 고침 — 재설치하면 알림이 조용히 멈췄다

**증상**
설정에서 알림을 켜둔 뒤 앱을 다시 설치하면, 설정 화면에는 `켜짐`인데 **알림이 오지 않았다.**

**원인**
예약해 둔 알림은 앱과 함께 지워지는데, 설정값만 남아 있어서 켜진 것처럼 보였다.

**고친 방법**
앱을 켤 때 설정이 `켜짐`이면 알림을 조용히 다시 예약한다 (`app/_layout.tsx`).

---

### 🟡 고침 — 하루에 '간식'이 두 번이면 체크 항목이 하나로 합쳐졌다

플랜에 `간식`이 두 번 들어 있으면 체크리스트에 하나만 나오고,
하나를 체크하면 나머지도 같이 체크된 것으로 취급됐다.
항목을 구분하는 이름이 끼니 이름뿐이라 서로 겹쳤다. 순번을 붙여 구분되게 했다.

---

### 🟢 고침 — 사진 파일이 없을 때 빈 회색 칸이 남았다

백업에서 복원하면 기록은 돌아오지만 **사진 파일은 백업에 없다**(용량 때문).
이때 빈 회색 네모가 줄줄이 남았다.
이제는 메모를 대신 보여주거나 `사진을 찾을 수 없어요`라고 알려준다.

---

### 🟢 고침 — 끝난 플랜이 계속 '35일차 / 28일'로 표시됐다

28일 플랜이 끝나도 날짜만 계속 올라갔다.
끝난 뒤에는 `이 플랜은 끝났어요. 수고했어요`로 바뀐다.

---

### 🟢 고침 — 화면을 열 때 '아직 비어 있어요'가 깜빡였다

기록을 불러오는 아주 짧은 순간 빈 화면 문구가 스쳐 지나갔다.
불러오는 동안에는 문구를 띄우지 않는다.

---

## 확인했지만 고치지 않은 것

| 본 것 | 판단 |
|---|---|
| 주간 요약에서 사진 20~30장을 한 번에 띄울 때의 메모리 | 지금 규모에서는 괜찮다고 봤다. 느려지면 그때 작은 미리보기 파일을 따로 저장하는 방식으로 바꾸는 게 맞다 |
| 백업 파일 이름이 한글(`냥집사-백업-....json`) | 공유하는 앱에 따라 이름이 바뀔 수 있으나 내용은 정상이라 그대로 뒀다 |
| 플랜 시작일이 미래일 때 | 정상. `9월 1일부터 시작해요`로 안내하고 체크리스트는 숨긴다 |
| 백업 JSON에 사진이 없는 것 | 의도된 동작. 사진까지 담으면 파일이 너무 커진다 |

## 라운드 3 — 실기기 설치 중 발견

### 🔴 고침 — 라운드 1의 푸시 알림 수정이 실제로는 듣지 않았다

**증상**
`ios` 폴더를 새로 만들자 예전에 봤던 오류가 그대로 다시 나왔다.

```
Personal development teams do not support the Push Notifications capability.
```

**원인 (내가 틀렸던 부분)**
`app.json`의 `plugins`에서 `expo-notifications`를 뺐으니 해결됐다고 봤는데, 아니었다.
**`expo-notifications`는 설치만 되어 있으면 `aps-environment` 권한을 자동으로 넣는다.**
지난번에 넘어갔던 건 Xcode에서 손으로 그 항목을 지우셨기 때문이고,
`ios` 폴더가 다시 만들어지면서 되살아났다.

실제로 `npx expo prebuild`를 돌려 생성된 권한 파일을 열어보고 확인했다.

**고친 방법**
`plugins/withoutPushNotifications.js` — 생성된 권한 목록에서 `aps-environment`만 지우는 작은 플러그인.
다시 생성해서 권한 파일이 비어 있는 것까지 확인했다. 로컬 알림은 그대로 동작한다.

---

### 🔴 고침 — 번들 ID가 되돌아가 기록이 날아갈 뻔했다

**증상**
`No profiles for 'com.cathealth.app' were found`

**원인**
번들 ID를 Xcode 화면에서만 `com.cathealth.app.seungheon`으로 바꿔뒀는데,
그 값은 `ios` 폴더 안에 있어서 폴더가 새로 만들어지면 `app.json` 기준으로 되돌아간다.

**왜 위험했나**
그대로 설치했다면 아이폰이 **다른 앱으로 인식**해서,
그때까지의 사진과 기록에 접근할 수 없게 된다.

**고친 방법**
`app.json`의 `ios.bundleIdentifier`에 `com.cathealth.app.seungheon`을 고정했다.
이제 `ios` 폴더를 몇 번을 새로 만들어도 같은 ID가 나온다.

---

### 배운 것

**"고쳤다"고 말하려면 결과를 봐야 한다.**
라운드 1에서는 설정 파일을 고친 것으로 끝냈는데, 실제로 생성되는 결과물을 확인하지 않았다.
이번에는 `prebuild`를 직접 돌려 권한 파일과 번들 ID를 눈으로 보고 확인했다.

## 라운드 4 — 고양이 모션

### 🔴 고침 — 그림이 두 곳에 따로 있어 어긋날 수 있었다

**증상**
`components/Cat.tsx`(앱)와 `tools/render_assets.py`(미리보기)에 **같은 도형이 복사되어** 있었다.
한쪽만 고치면 미리보기와 앱이 다른 고양이를 보여준다.
실제로 "이 그림이 앱에 나오는 그림"이라고 말할 근거가 없었다.

**고친 방법**
`lib/catArt.ts` 하나에서 SVG 문자열을 만들고, 앱과 미리보기 도구가 그 함수를 같이 쓴다.
파이썬 복사본은 지웠다. 이제 `npm run cat`으로 뽑은 그림은 앱 화면과 같을 수밖에 없다.

---

### 🟡 고침 — 밥그릇·물컵이 몸에 가려 안 보였다

처음 그린 밥 먹기/물 마시기는 그릇을 몸통보다 **먼저** 그려서 완전히 가려졌고,
고개만 살짝 내려서 "조금 작은 고양이"로 보였다.

- 그릇을 몸통보다 **뒤에** 그려 앞에 놓인 것처럼 보이게 함
- 머리를 통째로 26도 기울여 **귀가 몸통 밖으로 나오게** 함
- 그래야 정면 실루엣에서도 "고개를 숙였다"가 읽힌다

### 🟡 고침 — 뛰는 다리가 몸통에 묻혀 안 보였다

발이 몸통 타원 안쪽에서 오르내려서 아무 움직임도 보이지 않았다.
몸통을 올리고 줄여서 **발이 몸통 아래로 확실히 드러나게** 했다.

---

### 🟢 고침 — 눈 깜빡임 타이머가 계속 쌓였다

깜빡임을 예약할 때마다 배열에 타이머를 밀어 넣고 지우지 않았다.
화면을 오래 켜두면 수천 개가 쌓인다. 항상 하나만 살아 있게 바꿨다.

### 🟢 고침 — 고개 숙인 자세에서 감은 눈이 한 줄로 붙어 보였다

머리를 기울인 상태에서 눈을 감기면 두 선이 이어져 얼굴을 가로지르는 사선이 됐다.
밥 먹기/물 마시기는 1초 남짓 스쳐가는 자세라 **눈을 감기지 않기로** 했다.

## 라운드 4에서 판단만 하고 넘어간 것

| 본 것 | 판단 |
|---|---|
