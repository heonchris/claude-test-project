# 족저압 인솔 실시간 데모

시뮬레이션 데이터로 동작하는 프로토타입. 실제 센서 없이 앱의 핵심 화면을
확인하기 위한 것이다.

공개 링크: https://claude.ai/code/artifact/9dd7b3ea-5139-4486-a21a-469d276c64f7

## 실행

`index.html`을 브라우저로 열면 된다. 빌드 과정도 외부 의존성도 없다.

## 사업 정의서 대응

| 필수 구현 기능 | 구현 상태 |
|---|---|
| 1. 실시간 히트맵 시각화 | 구현 — IDW 보간, 발 외곽선 클리핑 |
| 2. 변화 추이 그래프 | 구현 — 12초 롤링 윈도우, 좌우 2계열 |
| 3. 실시간 스트리밍 렌더링 | 구현 — 30Hz 갱신 |
| 4. 리포트 자동 생성 | 구현 — 세트 종료 시 좌우·전후 판정 |
| 5. 장비/센서 연동 및 DB | 미구현 — 시뮬레이터로 대체 |
| 6. 크로스플랫폼 | 미구현 — 웹 프로토타입 |

## 채널 구성

발당 8채널 × 양발 = 16채널.

| ch | 위치 | ch | 위치 |
|---|---|---|---|
| 1 / 9 | 엄지 | 5 / 13 | 제5중족골두 |
| 2 / 10 | 2–3지 | 6 / 14 | 중족부 외측 |
| 3 / 11 | 제1중족골두 | 7 / 15 | 뒤꿈치 내측 |
| 4 / 12 | 제2–3중족골두 | 8 / 16 | 뒤꿈치 외측 |

원시값 범위 0~1023 (아두이노 10bit ADC 기준).

## 실제 센서로 교체할 때

`simulate()` 함수만 실제 BLE 수신 데이터로 바꾸면 나머지는 그대로 동작한다.
`vals.L[0..7]` 과 `vals.R[0..7]` 에 0~1023 값을 넣어주면 된다.

## 설계 판단 두 가지

**전후 균형은 채널 합계가 아니라 무게중심 위치로 계산한다.** 전족부 5채널과
뒤꿈치 2채널의 개수가 달라, 합계로 재면 히트맵이 보여주는 것과 반대 결과가
나온다.

**히트맵은 단일 색상 램프(파랑)를 쓴다.** 무지개 배색은 크기 순서가 눈에
읽히지 않아 압력 크기 표현에 부적절하다.

## 한계

- 시뮬레이션 데이터이므로 실제 FSR의 비선형성·히스테리시스는 반영되지 않음
- 리포트 판정 기준은 임시값이며 실측 데이터로 재조정 필요
- 의학적 진단이 아닌 운동 자세 피드백 범위로 문구를 한정함
