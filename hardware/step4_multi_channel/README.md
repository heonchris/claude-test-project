# 4단계 · 센서 여러 개

1채널 전 구간 연동이 끝난 뒤, 센서를 늘리는 단계다.

## 고칠 곳은 한 줄뿐

```cpp
const int PINS[] = { A0, A1 };              // 2개
const int PINS[] = { A0, A1, A2 };          // 3개
const int PINS[] = { A0, A1, A2, A3, A4, A5 };  // 6개 — 우노 한계
```

`PINS` 의 순서가 곧 채널 번호다. `A0` → ch1, `A1` → ch2.
어느 채널이 발의 어디인지는 앱의 **[설정] → [센서 위치 설정]** 에서 바꾼다.
배선을 다시 뽑을 필요가 없다.

## 배선에서 반드시 지킬 것

**센서마다 10kΩ 저항을 하나씩 따로 둔다.**

저항 하나를 여러 센서가 나눠 쓰면 한쪽을 누를 때 다른 쪽 값까지 같이
움직여서, 어느 센서가 눌린 것인지 구분할 수 없게 된다. 그래프는 나오는데
쓸 수 없는 데이터가 되므로 알아차리기도 늦다.

**5V 와 GND 는 반대로 전부 같이 쓴다.** 브레드보드 가장자리의 빨강·파랑
전원 레일에 한 번만 끌어오면 8개까지 그대로 쓴다.

### 센서 한 벌의 구조 (이것을 센서 수만큼 복제한다)

```
빨강 레일(5V) ── FSR ──┬── 아날로그 핀 (A0, A1, …)
                        │
                     10kΩ        ← 이 저항은 이 센서 전용
                        │
                   파랑 레일(GND)
```

## 핀

블루투스는 디지털 **4번**(모듈 TXD) · **5번**(모듈 RXD).
**3번은 쓰지 않는다** — 그 보드에서 고장나 있던 핀이다.
자세한 경위는 `../step2_bluetooth_test/README.md` 6절.

## 확인

| 보는 곳 | 정상 |
|---|---|
| 시리얼 모니터 | `ch1=12  ch2=430` — 누른 센서의 값만 올라간다 |
| 앱 [설정] → 센서 위치 설정 | 누른 센서의 줄만 초록색이 된다 |
| 앱 [측정] | 히트맵의 점이 센서 수만큼 따로 움직인다 |

**두 숫자가 같이 움직이면 저항을 공유한 것이다.** 10kΩ 을 하나 더 넣는다.

## 8채널로 갈 때

우노는 아날로그 핀이 `A0~A5` 여섯 개뿐이라 발당 8채널이 안 된다.
**나노(A0~A7)** 로 가면 멀티플렉서 없이 맞는다. 코드는 `PINS` 줄에
`A6, A7` 을 더하면 끝이다.

양발 구조와 패킷 분할은 `../../handoff/DATA_CONTRACT.md` 2-2절 참조.
