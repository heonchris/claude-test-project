# 펌웨어 — 어느 파일을 어느 보드에

## 실제로 쓰는 파일 5개

보드 한 대에 파일 하나. **코드는 고칠 것이 없다.**
`Tools > Board` 만 맞추고 업로드한다.

| 파일 | 보드 | 발 | 모듈 TXD → | 모듈 RXD → |
|---|---|---|---|---|
| `insole_L_uno` | Arduino Uno | 왼발 | **4번** | **5번** |
| `insole_R_uno` | Arduino Uno | 오른발 | **4번** | **5번** |
| `insole_L_nano` | Arduino Nano | 왼발 | **4번** | **5번** |
| `insole_R_nano` | Arduino Nano | 오른발 | **4번** | **5번** |
| `insole_R_mega` | Arduino Mega or Mega 2560 | 오른발 | **19번 (RX1)** | **18번 (TX1)** |

`VCC → 5V`, `GND → GND` 는 전부 같다.
센서는 `A0`·`A1`. **센서마다 10kΩ 저항을 하나씩 따로** 둔다 (공유 금지).

### 나노는 우노와 같은 칩이다

나노와 우노는 둘 다 ATmega328P 라 **코드도 핀 번호도 배선도 완전히 같다.**
파일을 따로 두는 이유는 부팅 첫 줄에 찍히는 보드 이름을 맞추기 위해서다.
우노용 파일을 나노에 올려도 동작은 하지만, 그러면 그 줄이 "우노" 라고
거짓말을 해서 똑같이 생긴 기기 여러 대를 구분할 단서가 하나 사라진다.

다른 것은 업로드 설정 하나뿐이다. 아래를 보라.

### 나노 업로드가 안 될 때 — Processor 를 바꾼다

```
avrdude: stk500_recv(): programmer is not responding
Error: programmer is not responding
Warning: attempt 1 of 10: not in sync: resp=0x00
```

**선도 보드도 멀쩡하다. 부트로더 선택이다.**
`Tools > Processor` 를 `ATmega328P` 와 `ATmega328P (Old Bootloader)`
두 가지로 번갈아 시도한다. 중국산 나노는 대부분 구형 부트로더를 쓰는데,
신형 115200 과 구형 57600 으로 **업로드 속도가 달라** 섞이면 보드가
말을 못 알아듣고 `resp=0x00`(무응답)만 돌아온다. 겉모습으로는 어느
쪽인지 알 수 없으니 그냥 둘 다 해 보면 된다.

#### 업로드 오류는 세 종류다. 섞어서 보면 엉뚱한 데를 고친다

업로드는 ① 포트를 찾고 → ② 포트를 열고 → ③ 보드와 대화한다.
오류 문구가 **어느 단계에서 멈췄는지** 말해 준다.

| 오류 | 멈춘 단계 | 볼 곳 |
|---|---|---|
| `Port` 목록에 번호가 없음 | ① 포트가 없다 | 코드 28 이면 **CH340 드라이버**, 코드 43 이면 **케이블·배선** |
| `cannot open port \\.\COMn` | ② 못 연다 | **시리얼 모니터**, 포트 번호 |
| `not in sync: resp=0x00` | ③ 대화 실패 | **Processor(부트로더)** |

②는 포트가 **있는데** 안 열리는 경우다. 드라이버는 멀쩡하다.
한 포트는 한 프로그램만 쓸 수 있어서, 누가 잡고 있으면 이렇게 난다.

1. **시리얼 모니터를 닫는다.** 1순위다. 열어 둔 채로 업로드하면
   IDE 가 알아서 놓아주기도 하지만, CH340 클론에서는 자주 실패한다.
2. **그 번호가 정말 이 보드인지 본다.** USB 를 뽑고 `Tools > Port`
   목록에서 **사라지는 번호**를 확인한 뒤 다시 꽂고 그 번호를 고른다.
   사라지지 않으면 다른 장치를 고르고 있었던 것이다.
3. **IDE 를 껐다 켠다.** 실패한 업로드가 포트 손잡이를 안 놓는 일이
   IDE 2.x 에서 흔하다.
4. 다른 IDE 창, PuTTY 같은 시리얼 프로그램을 모두 닫는다.

같은 보드에서 ③ 이 떴다가 ② 로 바뀌었다면 **보드와 드라이버는 이미
증명된 것이다.** ③ 까지 갔다는 것은 포트가 열렸었다는 뜻이므로,
그때는 ② 쪽만 보면 된다.

#### Old Bootloader 로도 안 되면

순서대로 본다. 위 두 개가 대부분이다.

1. **0·1번 핀에 꽂힌 것을 뺀다.** 업로드는 0(RX)·1(TX)로 간다.
   거기 무언가 물려 있으면 신호가 섞여 같은 오류가 난다.
   이 프로젝트는 블루투스를 4·5번에 두므로 해당 없지만, 임시로
   꽂아 둔 선이 있으면 뽑는다.
2. **업로드를 누른 직후 보드의 리셋 버튼을 한 번 누른다.**
   자동 리셋 회로가 부실한 클론에서 잘 듣는다. 컴파일이 끝나고
   `Uploading` 으로 바뀌는 순간이 맞다.
3. `Tools > Port` 가 나노의 번호가 맞는지. 번호가 아예 안 보이면
   그건 ① 이다 — "업로드가 안 될 때 — 선이 아니라 포트부터".
4. USB 허브를 빼고 본체 포트에 직접 꽂는다.

### 보드를 잘못 고르면 업로드 전에 막힌다

각 파일에 보드 검사가 들어 있어, 틀린 보드를 고르면 컴파일 단계에서
한글 오류가 난다. 조용히 안 되는 것보다 낫다.

```
이 파일은 우노용입니다. 메가에는 insole_R_mega 를 올리세요.
```

### 올린 뒤 확인

시리얼 모니터(9600) 첫 줄에 어느 파일·어느 보드로 돌고 있는지 찍힌다.

```
파일: insole_R_mega
보드: 메가 (하드웨어 Serial1 · 모듈 TXD->19, RXD->18)
발 R · 센서 2개로 시작합니다.
ch1=12  ch2=430
```

## 기기마다 블루투스 이름을 다르게

기기들이 겉모습도 코드도 같으므로 **휴대폰이 구분할 방법은 이름뿐이다.**
신발에 넣기 전에 `step2_bluetooth_test/at_check` 로 한 번씩 바꾼다.

```
AT+NAMEinsoleL1
```

이름을 바꾸는 즉시 **보드와 모듈과 인솔에 같은 글자를 테이프로 써 붙인다.**
똑같이 생긴 기기 6대는 반드시 섞인다.

## 눌러도 숫자가 안 오를 때

0~1023 중 **한 자리 수는 안 눌린 것과 같다.** FSR 은 안 눌렸을 때 수 MΩ,
꾹 눌렀을 때 수 kΩ 이다. 10kΩ 분압이면 눌렀을 때 **수백**이 나와야 한다.
눌러서 4 가 나왔다면 계산상 FSR 이 아직 2.5MΩ 이라는 뜻이고,
**힘이 센서에 안 닿았거나 회로가 안 닿은 것이다.** 센서는 멀쩡하다.

| 증상 | 1순위 원인 |
|---|---|
| **모든 채널이** 0 근처 | 5V 한 가닥. VIN·3V3 에 꽂았거나 5V 줄이 빠짐 |
| **한 채널만** 약함 | 그 채널만의 것 셋 — FSR, 10kΩ, 사이의 선 |
| 한 채널이 **0 에서 꿈쩍 않음** | 그 채널의 5V→FSR→핀 경로가 끊김 |
| 눌러서 **한 자리 수**만 | FSR 탭 접촉 불량. 다음이 저항값 |
| **1023 에 붙어 고정** | 10kΩ 이 빠져 핀이 5V 에 직결 |

안 누른 채널이 0 인 것은 **정상이다.** 0 을 고장으로 읽지 않으려면
판정은 반드시 누른 상태의 최고값으로 한다.

### 한 채널만 약할 때 — 바꿔 끼워 본다

다른 채널이 정상이면 5V·GND·보드·코드는 이미 증명된 것이다.
남은 것이 셋뿐이므로 **센서 두 개의 자리를 맞바꾼다.**

- 증상이 **센서를 따라가면** → 그 FSR 이나 그 탭의 접촉
- 증상이 **자리에 남으면** → 그 자리의 저항이나 선

한 번으로 둘 중 하나가 지워진다. 저항도 같은 방법으로 맞바꿔 본다.

### 10초 판정

A0 에 가던 선을 빼고 **5V 를 A0 구멍에 바로** 꽂는다.

- **1023 이 뜬다** → 보드·핀·코드 정상. 범인은 센서/저항/접촉
- **안 뜬다** → 5V 줄이나 핀 자리가 틀렸다. 센서는 볼 필요도 없다

그 다음은 `sensor_check` 를 올린다. 채널마다 내부 풀업을 잠깐 켜 보고
**"저항 쪽이 끊김"과 "5V 쪽이 끊김"을 갈라서** 한글로 찍어 준다.
풀업값은 그 핀에 매달린 저항을 재는 것이기도 하다. 10kΩ 이면 150~400,
아무것도 없으면 1023, 10Ω 처럼 너무 작으면 0 근처다. **채널끼리 비교해서
한쪽만 동떨어지면 그 채널의 저항이 범인이다.**

### FSR 탭은 원래 잘 빠진다

FSR-402 의 단자는 0.3mm 두께의 납작한 판이다. 브레드보드 구멍은 둥근
다리를 잡게 되어 있어서 **꽂혀 있어 보여도 안 물린 경우가 흔하다.**
센서를 누르면서 탭을 손가락으로 같이 눌러 숫자가 튀면 접촉 불량이다.

## 업로드가 안 될 때 — 선이 아니라 포트부터

`stk500v2_getsync()` · `unable to open port COM3` · `타임아웃` 이 뜨면
**블루투스 선을 만지지 마라.** 업로드는 USB 로만 일어난다. 모듈을 전부
빼놓고 USB 만 꽂은 상태에서 아래를 본다.

### 1. 윈도우가 보드를 보고 있는가

`장치 관리자` 를 연다.

| 보이는 것 | 뜻 | 조치 |
|---|---|---|
| `포트(COM & LPT)` 밑에 COM 번호 | 정상 | 그 번호를 IDE 에서 고른다 |
| `기타 장치` 밑에 `USB Serial` + 노란 느낌표 (코드 28) | **드라이버 없음** | 아래 2번 |
| 아무것도 안 뜬다 | 케이블이 충전 전용 | 데이터용 케이블로 교체 |

**COM 번호가 안 보이면 포트가 없는 것이다.** IDE 에 떠 있는 다른 COM 번호는
보드가 아니라 블루투스 가상 포트 같은 것이고, 그걸 고르면 정확히
`unable to open port` 가 난다.

### 2. 코드 28 — 호환보드의 CH340 드라이버

중국산 호환보드는 USB 칩으로 `CH340` 을 쓰는데 윈도우에 드라이버가 없다.
정품은 꽂으면 바로 잡히므로, 이 증상은 호환보드에서만 난다.

칩 확인: 장치 속성 → `자세히` → `하드웨어 ID` → `VID_` 뒤 네 글자.

| VID | 칩 | 드라이버 |
|---|---|---|
| `1A86` | CH340 / CH341 | WCH `CH341SER.EXE` |
| `0403` | FTDI | FTDI VCP |
| `2341` | 정품 아두이노 | 불필요 (USB 허브를 빼고 본체에 직접) |

설치는 두 가지 중 하나로만 한다. **검색해서 나오는 블로그 재배포본은 쓰지 마라.
악성코드를 끼워 넣은 것이 많다.**

1. 장치 속성의 `드라이버 업데이트` → `드라이버 자동 검색` (윈도우 업데이트)
2. 제조사 WCH: `wch-ic.com/downloads/CH341SER_EXE.html` → 관리자 권한 실행 → `INSTALL`

깐 뒤에는 **USB 를 뽑았다 다시 꽂고, IDE 를 껐다 켠다.** 그래야 새 포트가 보인다.
`포트(COM & LPT)` 밑에 `USB-SERIAL CH340 (COM5)` 처럼 생기면 성공이다.

### 2-1. 코드 43 — 드라이버와 무관하다

```
알 수 없는 USB 장치 (장치 설명자 요청 실패)   코드 43
```

코드 28 과 혼동하기 쉬운데 **전혀 다른 문제다.** 28 은 "누군지는 아는데
드라이버가 없다" 이고, 43 은 **"누군지도 모른다"** 이다. 윈도우가 장치에게
자기소개를 요청했는데 대답이 없었다는 뜻이라, 드라이버를 아무리 깔아도
소용없다. 전기적인 문제다.

| | 코드 28 | 코드 43 |
|---|---|---|
| 뜻 | 드라이버가 없다 | 장치가 대답을 못 한다 |
| 볼 곳 | CH340 드라이버 | **케이블 · 전원 · 배선 · 보드** |

#### 선을 전부 빼는 것이 1순위다

점퍼선·블루투스 모듈·센서를 **전부 뽑고 보드와 USB 만** 남겨서 꽂는다.

- 잡히면 **배선이 범인이다.** 5V 와 GND 가 어디선가 붙었거나 전류를
  과하게 먹고 있다. USB 전류 제한에 걸리면 보드가 켜지다 말아서 이
  증상이 난다. 선을 **한 번에 하나씩** 꽂으면서 장치 관리자를 보면
  어느 선에서 깨지는지 바로 나온다.
- 그대로면 아래 순서로.

1. **USB 케이블 교체.** 가장 흔하다. 충전 전용은 전선이 2가닥뿐이다.
   나노는 미니 USB 라 서랍의 오래된 케이블을 쓰게 되는데 그게 대개
   충전 전용이다.
2. **허브·연장선을 빼고 본체 뒷면 포트에 직접.** 장치 속성의 `위치` 가
   `Hub_#` 로 되어 있으면 허브를 거치는 중이다. 허브는 전류가 모자라기 쉽다.
3. **USB 커넥터를 살살 흔들어 본다.** 나노 V3 클론은 USB 소켓 납땜이 잘
   들뜬다. 나타났다 사라졌다 하면 납땜이 깨진 것이고, 보드 교체가 빠르다.
4. **다른 PC 에 꽂아 본다.** 거기서도 43 이면 보드 불량 확정이다.

#### 직전까지 포트가 보였다면 물리적인 것만 바뀐 것이다

`not in sync` 나 `cannot open port COMn` 이 떴었다는 것은 **그때는 USB 로
인식됐다**는 뜻이다. 그 뒤 43 으로 바뀌었다면 펌웨어도 드라이버도 아니고
그 사이에 만진 것 — 선, 케이블, 포트 — 뿐이다.

### 3. 메가는 Processor 도 본다

`Tools` → `Board` 를 `Arduino Mega or Mega 2560` 으로,
`Tools` → `Processor` 를 **`ATmega2560 (Mega 2560)`** 으로.
`ATmega1280` 으로 두면 포트가 맞아도 업로드 중에 멈춘다.

### 4. 그래도 코드 28

예전에 깔린 불량 드라이버가 남아 있는 경우다.
`CH341SER.EXE` 에서 `UNINSTALL` → 재부팅 → `INSTALL`.

| `at_check` | AT 명령을 직접 쳐야 할 때 (이름 바꾸기 등) |

| `pin_check` | 선이 전기적으로 붙어 있는가 |
| `pin_monitor` | TXD 인지 STATE 인지 가려내기 |
| `sensor_check` | 센서값이 0 이거나 눌러도 안 오를 때. 채널별로 원인을 찍어 준다 |
