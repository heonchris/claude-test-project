# 해체 사례

진단이 어느 정도로 구체적이어야 하는지 보여주는 실제 사례 두 건.
공통점 하나만 기억하면 된다 — **모든 지적은 "돌리면 무슨 일이 벌어지는가"로 뒷받침된다.**
그 문장을 못 쓰겠으면 그건 지적이 아니라 취향이다.

---

## 사례 1 — 릴스 효과음 생성 프롬프트

### 원문 요약

10년 차 사운드 디자이너 역할. 영상을 받아 자막·전환 시점을 분석하고,
효과음 트랙 1개와 BGM 1개를 각각 별도 파일로 생성. 인터뷰 → 분석 → 큐시트 → 생성 → 검증 순서 엄수.
피크 −6dBFS, BGM −20 LUFS, 파이썬(pydub·librosa)으로 처리. 마지막에 체크리스트 출력.

### 슬롯 분해

| 슬롯 | 현재 내용 | 상태 |
|---|---|---|
| 역할 | 10년 차 사운드 디자이너 | 채워짐 |
| 과업 | 효과음·BGM 트랙 생성 | 채워짐 |
| 맥락 | 숏폼 편집 환경, 사용자 취향 인터뷰 | 채워짐 |
| 산출물 | 오디오 파일 2개, 병합 금지 | 채워짐 |
| 재료 | — | **비어 있음** |
| 역량 | pydub·librosa 지정 | **틀림** |
| 기준 | −6dBFS / −20 LUFS | 약함 |
| 검증 | "✓" 체크리스트 | **선언** |

### 진단

**① 재료 슬롯이 비었다 — 약속 후 실패**
"톡", "슉", "딸깍"을 무에서 만들 방법이 프롬프트 어디에도 없다.
지정된 pydub·librosa는 오디오를 *처리*하는 라이브러리이지 *생성*하는 라이브러리가 아니다.
→ 돌리면: 큐시트 승인까지 사용자를 끌고 간 뒤 마지막 단계에서 "만들 수 없습니다"로 끝난다.
→ 채우는 법: 조달 경로를 우선순위로 명시한다. A. 사용자 제공 팩 → B. numpy 절차적 합성(레시피까지 프롬프트에 박는다: 팝 = 사인 800→200Hz 글라이드 40ms + 지수감쇠 τ=25ms) → C. 외부 생성 API. 각 경로의 품질 한계를 미리 밝히게 한다.

**② 역량 슬롯이 틀렸다 — 조용한 표류**
LUFS는 ITU-R BS.1770 측정이고 pydub의 `dBFS`는 RMS다. 다른 값이다.
→ 돌리면: 모델이 RMS를 계산해 놓고 "−20 LUFS로 맞췄습니다"라고 보고한다. 사용자는 틀린 숫자를 믿는다.
→ 채우는 법: 지표별로 필요한 도구를 정확히 지정하고(pyloudnorm), 없을 때의 규칙을 함께 넣는다 — "측정할 수 없으면 그 단어를 쓰지 말고 실제 측정한 것의 이름으로 보고하라."

**③ 기준 슬롯이 절대값이라 무의미하다**
플랫폼이 최종 믹스를 −14 LUFS로 정규화하므로 "BGM −20 LUFS"는 그 자체로 의미가 없다.
→ 채우는 법: 음성 대비 상대값으로 바꾸고(−12~−18 LU), 기준끼리 충돌할 때의 우선순위를 넣는다.

**④ 검증이 선언이다 — 셀프 합격**
`"효과음 트랙 ✓"`는 모델이 타이핑하면 그만인 문자열이다.
→ 채우는 법: 목표와 실측을 나란히 놓은 표. 미달 항목은 ✗로 표시하고 재처리, 전부 통과했을 때만 "검증 통과"라고 쓰게 한다.

**⑤ 순서가 뒤집혀 있다**
인터뷰가 영상 분석보다 앞에 있다 — 보지도 않은 영상의 장르를 사용자에게 묻는 구조다.
→ 채우는 법: 접수 → 자동 분석 → 분석이 못 정한 것만 질문. 질문 4개가 2개로 준다.

### 배울 점

빈 슬롯 다섯 개 중 넷이 **실행 층**이었다. 요청 층(역할·과업·맥락·산출물)은 처음부터 완벽했다.
잘 쓰인 프롬프트일수록 남은 결함은 실행 층에 몰려 있다 — 거기부터 보라.

## 사례 2 — 데이터 정리 프롬프트

### 원문

> 너는 꼼꼼한 데이터 분석가야. 첨부한 매출 엑셀을 깨끗하게 정리해 줘.
> 중복 제거하고, 날짜 형식 통일하고, 이상치 처리하고, 보기 좋게 만들어서 다시 줘.

### 슬롯 분해

| 슬롯 | 현재 내용 | 상태 |
|---|---|---|
| 역할 | 꼼꼼한 데이터 분석가 | 약함 (판단 기준을 안 바꿈) |
| 과업 | 정리 | 약함 (동사가 넷) |
| 맥락 | 매출 엑셀 | 약함 |
| 산출물 | "보기 좋게" | **비어 있음** |
| 재료 | 첨부 파일 | 채워짐 |
| 역량 | — | 비어 있음 (이 과업엔 무해) |
| 기준 | — | **비어 있음** |
| 검증 | — | **비어 있음** |

### 진단

**① 기준 슬롯이 비었다 — 조용한 표류**
"이상치 처리"에 판단이 세 번 들어간다. 무엇이 이상치인가, 지우는가 표시하는가, 경계값은.
"중복"도 마찬가지다 — 전체 행이 같아야 중복인가, 주문번호만 같으면 중복인가.
→ 돌리면: 결과가 나오긴 하는데 매번 다르고, 왜 47행이 사라졌는지 설명할 수 없다. 매출 데이터에서 이건 조용한 손실이다.
→ 채우는 법: 판단이 들어가는 자리마다 규칙을 박는다. "중복 = 주문번호 기준, 최신 수정일 행을 남긴다 / 이상치 = 삭제하지 않고 `flag_outlier` 열에 표시한다 / 경계 = IQR 1.5배."
*삭제 대신 표시*가 기본값이어야 하는 이유도 함께 쓴다 — 되돌릴 수 있어야 하니까.

**② 산출물 슬롯이 비었다**
"보기 좋게"는 서식인가, 파일 형식인가, 열 순서인가.
→ 채우는 법: "원본 시트는 그대로 두고 `cleaned` 시트를 추가한 xlsx 파일 1개."

**③ 검증 슬롯이 비었다 — 셀프 합격**
→ 채우는 법: 처리 전후 행 수, 제거된 중복 수, 표시된 이상치 수, 형식이 바뀐 날짜 수를 표로 출력하게 한다. 사용자가 눈으로 대조할 수 있는 숫자여야 한다.

**④ 역할이 장식이다**
"꼼꼼한"은 판단을 바꾸지 않는다.
→ 채우는 법: "원본을 절대 덮어쓰지 않고, 판단이 필요한 곳마다 근거를 남기는 데이터 분석가."
이제 역할이 실제로 행동을 결정한다.

### 개선판

```
# 역할
원본을 덮어쓰지 않고, 판단이 필요한 자리마다 근거를 남기는 데이터 분석가.
규칙이 애매한 곳은 임의로 정하지 말고 물어본다.

# 과업
첨부한 매출 엑셀에서 중복·날짜형식·이상치를 정리한 사본 시트를 만든다.

# 산출물
xlsx 파일 1개. 원본 시트는 그대로 두고 `cleaned` 시트를 추가한다.
`cleaned`에는 `flag_outlier`, `flag_date_fixed` 두 열을 덧붙인다.

# 기준 (임의 판단 금지)
- 중복: 주문번호 기준. 같은 주문번호가 여럿이면 최신 수정일 행만 남긴다. 수정일이 같으면 지우지 말고 물어본다.
- 날짜: 모두 YYYY-MM-DD. 해석이 갈리는 형식(03/04/2025)은 지우거나 추측하지 말고 목록으로 보고한다.
- 이상치: IQR 1.5배 밖. 삭제하지 않고 `flag_outlier`에 표시만 한다. 되돌릴 수 있어야 하기 때문이다.

# 검증
작업 후 아래 표를 출력한다. 숫자는 실제 세어서 채운다.
| 항목 | 값 |
| 처리 전 행 수 | |
| 처리 후 행 수 | |
| 제거된 중복 | |
| 표시된 이상치 | |
| 형식 변환된 날짜 | |
| 판단 보류하고 보고한 행 | |
```

### 배울 점

일상적인 요청일수록 기준 슬롯이 비어 있다.
"이상치 처리해 줘" 같은 문장은 **판단 세 개를 이름 하나로 감춘다.**
해체는 그 감춰진 판단을 도로 꺼내 숫자로 적는 일이다.
